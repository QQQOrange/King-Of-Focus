# King Of Focus · Android

与桌面版同一套自律模型：**自律时段（7×24）→ 番茄（专注/休息循环）→ 名单拦截 → 积分**。
但 Android 的沙箱决定了有些能力**不可能**照搬，下面把每一条都写清楚，避免"看起来一致、实际做不到"。

## 一、能力映射（桌面版 → Android）

| 桌面版功能 | Android 实现 | 说明 |
|---|---|---|
| 规则名单（软件） | ✅ 已安装应用多选（包名） | 名单存在本机 JSON |
| 规则模式（黑/白名单） | ✅ blacklist / whitelist | 白名单自动放行系统壳（桌面、输入法、设置），否则手机会变砖 |
| 自律时段 7×24 小时网格 | ✅ 与桌面版同语义 | 10/15 分钟一格；**一小时可以有多段**（`wins`），每段带自己的 `seg`；相邻但不同段不合并 |
| 番茄（专注 N / 休息 M） | ✅ 完全一致 | 相位锚点=整点，`offset % (work+brk)` 取模，尾段截断 |
| 阶段提醒 | ✅ 系统通知 | 每个阶段只响一次，剩余时间跳大视为新阶段 |
| 应用拦截 | ✅ 前台检测 + 回桌面 + 通知 | 不再盖全屏拦截页（那层"专注遮罩"在手机上盖不严）；**不能结束别的应用进程** |
| 锁机（整台手机先别用） | ✅ 回桌面 + 全屏遮罩 | 不杀进程、不关机：先把前台应用送回桌面，再立刻盖上遮罩；温和模式可用积分换自由，强制模式没有出口 |
| 时段粒度 | ✅ 10 / 15 分钟一格 | 纵向时间、横向星期；一格多段也支持（`wins`） |
| 前台识别（无障碍） | ✅ AccessibilityService | 切应用即时得知；不需要「使用情况访问」，也不受 1 秒轮询的延迟影响 |
| ADB 级能力（Shizuku） | ✅ 可选 | 没悬浮窗也能拉起遮罩、强制模式弹掉设置页、无障碍被关后自愈。**不装也能用，只是弱一档** |
| 网页拦截（浏览器插件） | ❌ 未实现 | 需要 VPNService 或无障碍服务抓 URL，属高敏感权限，不在本版范围 |
| 专注遮罩（盖住其他窗口） | ⚠️ 拦截页 / 锁机遮罩本身即全屏 | Android 不允许盖住别人的窗口并保持最上层（除悬浮窗，且不能阻止交互） |
| 固化（不可退出、杀任务管理器） | ⚠️ 逻辑保留 | 只能"拒绝在应用内关闭自律"；系统设置里强行停止本应用无法阻止 |
| 任务管理器封杀 / 关机 | ❌ 不可实现 | 平台不提供；桌面版的"睡眠时段关机"在 Android 上是"勿扰/定时静音"的范畴，未做 |
| 全局热键 | ❌ 不可实现 | 改为通知栏常驻 + 桌面快捷方式 |
| 积分（专注每分钟 +1 / 解锁） | ✅ | 解锁期间所有拦截暂停（与桌面版修复后的语义一致） |
| 统计报表 | ✅ 与桌面版同口径 | 双轨（自律生效中 / 时段外 / 汇总）+ 今日·本周·本月 + 分时 + 排行 + 连续使用段；报表自动生成没搬（手机端手动生成文本报告） |
| 备份 / 恢复 | ✅ **与桌面版互通** | 同一份 `.kofbak` 格式（`docs/backup-format.md`），覆盖 / 合并两种模式 |
| 云同步 / 自动更新 | ❌ 未实现 | 依赖桌面端的 WebDAV 与 GitHub 更新链路 |

**一句话**：能自律的部分做到了行为一致；涉及"管别的应用 / 管操作系统"的部分，Android 不允许，本版改为"看住前台 + 全屏劝返"。

## 二、权限（为什么每一项都必须）

| 权限 | 用途 | 不给会怎样 |
|---|---|---|
| `PACKAGE_USAGE_STATS`（使用情况访问） | 唯一能读"当前前台是哪个应用"的公开通道 | 无法检测，等于没有拦截 |
| `SYSTEM_ALERT_WINDOW`（悬浮窗） | 部分 ROM 上拦截页需要它才能盖住 | 拦截页可能被目标应用压下去 |
| `POST_NOTIFICATIONS` | 阶段提醒 + 常驻状态 | Android 13+ 收不到提醒 |
| `FOREGROUND_SERVICE(_SPECIAL_USE)` | 每秒守护循环 | 后台被冻结，时段完全不生效 |
| `QUERY_ALL_PACKAGES` | 列出可拦截的应用 | 应用选择器为空 |
| 无障碍服务（`BIND_ACCESSIBILITY_SERVICE`） | 即时前台识别 + 回桌面 + 强制模式挡住设置页 | 退回 1 秒轮询，防绕过只剩下按返回 |
| Shizuku（`moe.shizuku.manager.permission.API_V23`） | 不受后台限制拉起遮罩、弹掉设置、自愈无障碍 | 需要「悬浮窗」权限兜底，防绕过弱一档 |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复守护 | 重启后要手动打开一次 |

## 三、构建

前置：JDK 17、Android SDK（platform 35 / build-tools 35.0.0）。

```bash
cd android
# local.properties 里写 sdk.dir，例如 C:\\dev\\android-sdk
gradle assembleDebug          # 产物 app/build/outputs/apk/debug/app-debug.apk
gradle testDebugUnitTest      # 时段/番茄/拦截判定的单测
```

本机使用的工具链：微软 OpenJDK 17 + cmdline-tools 11076708 + Gradle 8.9 + AGP 8.7.3 + Kotlin 2.0.21。

### 锁机

「设置 → 锁机」打开后：专注段里一离开允许的应用，就**先回桌面、再立刻盖上全屏遮罩**
（不杀进程、不关机——Android 本来也不允许，而且那会毁掉用户手上的东西）。

遮罩上有四样东西：

| 操作 | 行为 |
|---|---|
| 暂停锁机 | 花「暂停消耗」分（默认 10 分）换「暂停时长」分钟（默认 10 分钟）；到点自动重新锁机 |
| 停止锁机 | 花「停止消耗」分（默认 30 分）把**当前这一段**整个关掉；下一段专注重新锁机 |
| 允许的应用（N） | 点开是白名单格子，点任意一个直接跳过去；从它返回时遮罩仍在 |
| 长按底部小字 | 强制解除（不计分，仅限紧急）——宁可留一条不光采的逃生口，也不能让人打不出电话 |

两个价格都写在按钮上，点之前就能看到；积分不够只提示、不扣分、遮罩不动。

**必须授予「悬浮窗」**：没有它，后台拉起遮罩会被系统按"后台启动 Activity"拦掉
（锁机会静默失效）。所以打开锁机时如果没授权，应用会直接带你去授权页；
真缺权限时也会发一条"锁机没生效：缺「悬浮窗」权限"的通知，而不是假装在工作。

不需要「锁机」时，原来的「拦截」照旧：命中名单就弹一页拦截页。

### 允许使用的应用只有一份名单

锁机遮罩上的「允许的应用」**不再有独立配置**：它就是「规则」页里那些
**白名单规则**的并集（`GuardEngine.allowedPackages`）。以前锁机有自己的一份
`lockAllow`，于是常常出现"遮罩里能点开、规则却把它送回桌面"，同一个应用两处配置打架。

升级时老的 `lockAllow` 会自动并成一条名为「允许的应用」的白名单规则，不会丢。
设置页里那一栏现在只做只读展示，改的地方在「规则」。

### 白名单模式怎么执行

- **名单内**：放行（系统桌面、输入法、设置永远放行，否则手机变砖）
- **名单外**：先回桌面，然后
  - 有 Shizuku → `am force-stop` 把它**真的关掉**（这是 Android 上唯一能做到"强制退出"的路径）；
  - 没有 Shizuku → 只能回桌面 + 一条通知（系统不允许一个应用结束另一个应用）。
- 触发条件三者必须同时成立：**自律总开关开 + 在时段内 + 规则是启用状态**。
  规则页顶部会直接写出当前是哪一条没满足，不用猜。

### 温和 / 强制

| | 温和（默认） | 强制 |
|---|---|---|
| 暂停 / 提前结束 | 花积分，价格写在按钮上 | **完全没有**（不是置灰） |
| 长按强制解除 | 有（仅限紧急） | **没有** |
| 结束方式 | 积分 / 白名单 / 等到点 | 只能等这一段走完 |
| 切换 | 随时可切到强制 | **强制锁机进行中不许切回温和**（否则就是一步绕过） |

强制模式还会额外要求：至少一种前台识别、能把遮罩盖上来。缺哪一块，设置页直接用红字指出来
（缺识别 / 缺遮罩 / 缺 Shizuku），而不是让你打开一个"看起来在管、其实管不住"的模式。

### 防绕过

| 用户会做的事 | 应对 |
|---|---|
| 重启手机 | `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` → 起前台服务 → 第一拍恢复遮罩 |
| 从最近任务划掉 / 被 ROM 清后台 | `START_STICKY` + `onTaskRemoved` 补发 1.5 秒闹钟 + **15 分钟心跳广播** |
| 进设置强制停止 / 关无障碍 | 无障碍把那几页按返回；有 Shizuku 时直接把设置弹掉，并自动把无障碍写回启用列表 |
| 卸载本应用 | **拦不住**（要 Device Owner）；界面上照实写 |

三个必须承认的天花板：
1. **在设置里点过「强制停止」之后，任何广播都收不到**（`stopped=true`），
   直到用户手动再打开一次 —— 这是 Android 规则，没有任何非系统应用能绕过；
2. 卸载 / 清除数据拦不住（`no_control_apps` 需要 `MANAGE_USERS`，shell 拿不到，实测 `SecurityException`）；
3. 安全模式、root、换 ROM 一律无效。

设计细节、降级矩阵、时序图见 **`docs/android-guard-design.md`**。

### 这一版补的东西（0.3.0）

- **多套时段方案**：卡片式切换、新建（空表）、复制这套、重命名、删除；最多 12 套（与桌面版同上限）。
  每套各自 7×24 排班 + 通用番茄时长。
- **每套时段绑定哪些自律规则**：芯片里勾「全部」或具体分组。空 = 全部生效（老配置语义）。
  于是「工作日那套只管工作类、周末那套只管娱乐类」可以在一台手机上共存。
- **专注段生效中整页只读**：能改表就等于能把自律关掉，所以专注段里网格、方案、绑定、番茄默认值全都点不动
  （顶部有一行红字说明）。积分解锁 / 暂停锁机 / 停止本段之后即可编辑——这三个都是用户付过代价的出口。
- **段（seg）语义与桌面版一致**：一次拖选算一段；紧挨着已有段再点一格是**新的一段**。
  「停止本段锁机」按段身份失效，不是按"连续几个小时"。
- **通用番茄时长只影响之后新选的时段**：已经排好的小时各自记着自己的节奏；
  要统一改，用「应用到已选时段」（会二次确认，且跳过已经过去/锁住的星期）。
- **点一下定起点，长按之后才能拖**：网格比屏幕高，要能在格子上起手滚动。
  所以"框选"不抢占普通滑动——点一格定起点（画一圈描边），长按约 0.5 秒进入拖选
  （有触感反馈），此后上下拖动才框选，反向拖回去即撤销；
  **未长按的上下滑一格都不改，只滚动页面**。鼠标与触控走同一条判定。
- **十分钟 / 十五分钟刻度**：网格不再只能整小时——刻度可以切到 10 或 15 分钟，
  一格就是那么久。刻度只改画法不改数据：窗口永远按分钟存，换刻度不会让已排好的时段失效，
  旧边界跨在格子中间时画成浅色半格，重涂一下即对齐。
- **只改今天及之后**：网格里"今天之前"的星期是锁的（灰掉、标一个「锁」），
  点了会说明原因；写入路径也会再判一次（`ScheduleRules`），不是只把界面点灰。
  每周一自动解锁，已排的计划照常生效。
- **每天可以一键清空**：点表头 → 「全选」/「清空这一天」，清空前有二次确认。
- **坐标轴**：**时间是纵轴、星期是横轴**（和课程表一致）。24 小时纵向排得下，
  7 列宽度够手指点；反过来 7 行 × 24 列每格只有几毫米，点不住。
  格子上拖 = 框选，左侧时间刻度条上滑 = 滚动网格。
- **睡眠时段**：到点整机锁住（回桌面 + 遮罩），可用积分解锁一小段；支持多段与跨夜。
### 使用统计（口径与桌面端 `stats.rs` 一致）

- **每秒结算一次**，按**实际经过的秒数**记账（定时器漂移不再让总时长偏小）。
  跨整点、跨天由 `StatsMath.slices` 切开——23:59:58 的两秒不会算进第二天；
  系统把服务冻结很久之后的一次补账最多按 5 分钟计（那段时间人根本不在）。
- **双轨**：`on`（自律生效中）/ `off`（其余时间）两套完全隔离。
  「生效中」的判定与拦截同一个口径：规则生效 || 时段专注 || 锁机（`StatsTrack`）。
  统计页三档：自律时段内 / 时段外 / 汇总（汇总 = 两轨相加，不做加权）。
- **只算"你在用"**：熄屏、锁屏、停在桌面/自家界面一律不计，并封口当前连续段。
  桌面端用 `GetLastInputInfo` 判断人还在不在，Android 没有等价 API——
  所以默认「亮屏 + 未锁屏」即算；关掉「只看屏幕亮着」后还要求 60 秒内有过
  无障碍事件（没授权限时如实说明这项不生效，不假装生效）。
- **按小时装桶 + 连续使用段（spans）**：桶回答"这一小时用了多久"，
  段回答"几点到几点在用"（明细里点开某个应用就能看到）。
- **统计独立于自律开关**：`GuardService.shouldRun = 自律开 || 统计开`。
  以前关掉自律服务就停了，于是「时段外」那一轨永远是空的。
- 数据一天一个 JSON，默认保留 **400 天**（与桌面 `retention_days` 同值，可调）；
  老格式（分轨之前的 `apps` 映射）读进来落到「时段外」，并在明细里注明没有段。
- **页面结构（与桌面同构，按手机纵向重排）**：
  1. **饼图**：甜甜圈 + 中间合计 + 前 4 名图例；点某一块 = 选中这一项（明细里高亮展开）。
     桌面 620×360 才撑得开的引导线手机放不下，所以只画环、把名字放图例里。
  2. **日历**：默认当日 24 小时竖轨（位置=开始时刻，高度=用了多久）；
     切「按周」变成 7 列竖轨（每列一天，点列进当日）；切「按月」变成 7 列月网格
     （每格：日号 + 当天总时长 + 一条横向 24 小时色条，点格进当日）。
     **饼图与日历共用同一个周期状态**：换视图/翻页/切档，两块一起变。
  3. **耗时明细**：色点 + 名称 + 时长 + 占比 + 占比条，点开看连续使用段；
     段按当前档位筛（选「自律时段内」时不会混进时段外的段）。
  4. **报告**：累计 / 日均 / 最长的一天 / 用得最多 / 峰值小时，可复制或分享。
- **配色单一来源**（`StatsCal.colorSlots`）：饼图前 8 名先占色，日历与明细沿用同一份，
  同一个应用在饼图/日历/列表里永远是同一个颜色（与桌面 `PALETTE` 同一组 12 色）。
- **日历窗口**：一周从周一开始；月视图铺满整周（`weekStart(1 号)` 到 `weekStart(月末)+6`），
  网格永远是 7 的倍数，不会出现"月末挤成半行"。
- **WebDAV 云同步**：上传/下载/测试连接，冲突按 `updatedAt` 谁新听谁的；凭据不上云。
- **图标统一**：安卓 launcher 与插件图标都来自桌面端同一张 `src-tauri/icons/icon.png`。
- **去掉专注遮罩**：命中规则改为「回桌面 + 一条通知」；锁机遮罩保留（那是用户明确要的）。

### 备份互通

「设置 → 备份与恢复」：填一个**和桌面端相同**的备份密码 → 「导出备份…」得到 `.kofbak`，
桌面端「从文件恢复…」直接能用；反过来也一样。恢复时选「覆盖」或「合并」：

- **覆盖**：用备份里的规则、时段、积分、提醒替换本机（拦截页文案这类手机专属设置不动）
- **合并**：只补本机没有的规则和时段；同 id / 同内容跳过，同名不同内容改名并列；积分取较大值

实现细节、去重指纹、加密参数见 `docs/backup-format.md`。
两端测试读的是同一份样例（`tools/fixtures/`），其中 `portable-enc.json` 是**桌面端代码加密**出来的，
手机端单测会真的把它解开——这样"兼容"是可验证的，而不是口头承诺。

## 四、安装与首次使用

1. `adb install -r app/build/outputs/apk/debug/app-debug.apk`
2. 打开应用 → 总览页按提示授予「使用情况访问」「通知」（悬浮窗视机型）
3. 「时段」页点亮要自律的小时；「规则」页新建规则并勾选应用
4. 回到总览打开「启用自律」→ 常驻通知出现即生效

## 五、已知限制（如实列出）

1. **不能杀进程**：拦截是"拉回拦截页"，用户按 Home 键仍可离开，再次打开会立刻被拉回。
2. **按 Home 可绕过**：这是设计取舍——不给出口会把手机锁死，属故障而非自律。
3. **国产 ROM 会杀后台**：需要在系统设置里给本应用"允许后台运行 / 忽略电池优化"。
4. **卸载或撤销权限即可绕过**：Android 上没有"防卸载"的合规手段。
5. **网页拦截缺失**：需要 VPN/无障碍，本版未做。

## 六、代码结构

