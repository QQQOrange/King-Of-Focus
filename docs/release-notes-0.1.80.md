# 0.1.80

统计页这一版只解决一件事：**让数字说明它自己是怎么来的**，并多了一个真正会促成改变的入口。

## 一、每个关键数字旁边都有「?」

统计页最容易被误读的不是数字，而是"这个数字是什么意思"。误读一次，用户就会开始
怀疑整套数据，然后关掉统计。所以五处关键位置都挂了小问号，点开是一段解释：

| 位置 | 回答的问题 |
|---|---|
| 双轨切换旁 | 为什么分成两条轨——什么条件才算"自律模式已开启" |
| 使用时长分布标题 | 这些秒数是怎么来的（域名 vs exe、采样频率） |
| 当日日历标题 | 为什么这一小时算"未自律" |
| 24 小时分布标题 | 24 根柱子到底是"某一天"还是"累计" |
| 采集口径说明 | 离开的时间去哪了（无输入 60 秒不计时） |

最要紧的是第一条。`今日自律 2 小时` 的意思是"今天有 2 小时是在自律状态下的使用时间"，
不是"今天学了 2 小时"——这句话以前只在卡片下方一段长得像免责声明的小字里，
现在点在问号上就能看到，还写清了三条判定条件。

## 二、周复盘（统计报告页顶部）

不做"再生成一份周报"。报告是数据，复盘是决定；一份周报可以从头看到尾，
然后什么都不会改变。

所以这里是**五个问题，每个问题前面挂着已经算好的数字**：

1. 本周自律 X（上周 Y），最投入的是哪天 → 「这周最好的一天是哪天？那天你做对了什么？」
2. 被打断 K 次、最多来自 A（n 次）→「下周要不要把它关掉？关不掉的话替代办法是什么？」
3. 有 D/7 天写了段目标 → 「没写目标的那几天，你其实在做什么？」
4. 记下 P 条分心事件、处理了 Q 条 → 「还剩 R 条，哪一条值得现在就处理？」
5. 质押结算 N 笔、干净跑完 M 笔、没收 K 笔 → 「下周只改一件事——改哪件？」

回答存在本机（`reviews.json`），按周存档，下次打开同一周还能看到，用来对照。
第 5 题的提示就写着"只写一件。写两件等于没写。"

数据全部来自已有文件（统计日文件、账本、分心事件、段目标、质押），在 Rust 侧
`review::week` 汇总——**复盘看到的数字必须和统计页是同一份数据**，另算一套的话，
用户会先怀疑数字，再怀疑软件。
