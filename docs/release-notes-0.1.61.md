# v0.1.61 · 手机与桌面真正互通：同一个 WebDAV 目录，同一份备份

安卓 **0.3.8**。桌面端功能不变，但**云端备份列表多了一个来源标记**，并且不再删手机的备份。

## 问题：以前两端各传各的，互相读不了

| | 手机 | 桌面 |
|---|---|---|
| 云端文件 | `kof-android.json` | `king-of-focus.json` |
| 内容 | 手机的 `Config` 序列化 | 桌面的 `Config` 序列化 |
| 谁能读 | 只有手机 | 只有桌面 |

结果是：**手机上排好的时段，桌面上永远看不到**；桌面上调的规则，手机也拿不到。
两端各自"同步成功"，但同步的是两份互不相干的东西。

## 现在：一条通道，两端都认

两端唯一都认的是**跨设备备份文档**（`.kofbak`，`kof-portable` schema 1，
PBKDF2-HMAC-SHA256 + AES-256-GCM）。而桌面端的「备份 → 云端」本来就在以 `.kofbak` 为单位工作，
所以这条路不需要给任何一端加新格式：

| 动作 | 云端文件 | 另一端怎么用 |
|---|---|---|
| 手机「上传本机」 | `kof-<时间>-android.kofbak` | 桌面「备份 → 云端」里标 **手机**，点「恢复」 |
| 桌面「上传当前配置」 | `kof-<时间>.kofbak` | 手机「云同步」列表里标 **桌面**，点一下选合并 / 覆盖 |
| 手机「自动备份」 | `kof-auto-android.kofbak`（固定名覆盖） | 同上，标 **自动** |
| 手机「测试」 | 探针文件，用完即删 | 桌面列表会过滤掉它，不会出现在恢复列表里 |

## 几个必须做对的地方

**1. `PROPFIND` 得自己发。** Android 的 `HttpURLConnection` 把方法名限定在
`[OPTIONS, GET, HEAD, POST, PUT, DELETE, TRACE, PATCH]`，发 `PROPFIND` 直接抛
`ProtocolException: Expected one of [...] but was PROPFIND`。而 WebDAV 列目录**只有**
这一个办法——不解决它，手机就只能盲传一个固定文件，看不见桌面传上来的东西。
新增 `data/HttpRaw.kt`：一个 socket 发一条请求，带 TLS 主机名校验、chunked 响应、
一次重定向。不为一个请求引一个 WebDAV 库。

**2. 清理不能跨端误删。** 桌面原来按整个列表的序号保留最近 10 份——手机多传两份就会
把电脑的旧备份挤掉，更糟的是两端会互相删对方的文件，用户只会看到"另一台的备份丢了"。
现在桌面只清理**本机来源**的备份，手机传的（`-android`）一律跳过。

**3. 局域网 NAS 多是 http。** Android 9+ 默认拒绝明文，桌面不受这个限制，
于是会出现"电脑能同步、手机连不上"。已放开（`usesCleartextTraffic`），
并在界面里对 `http://` 地址明确红字提示"账号密码和备份内容在局域网里可见"。

**4. 凭据不进备份。** WebDAV 账号、备份口令都只留在本机，文档里没有这两节。

## 验证（AVD + 本地 WebDAV 服务器）

| 场景 | 结果 |
|---|---|
| 手机「刷新列表」 | 看到 `桌面 · 10-31 12:00 / kof-20261031-120000.kofbak · 23 KB` |
| 点它 →「合并」 | 规则 `桌面：工作类` 进来；积分取较大值 777；周一 09:00 选中（连 `seg=dseg1` 一起）；周一 10:00 没被误改 |
| 手机「上传本机」 | 服务器出现 `kof-20261031-132155-android.kofbak`（42 KB）；列表刷新后标「手机」 |
| **桌面 Rust 解析这份手机产物** | **成功：1 条规则、1 个选中小时**（`source=android`） |
| 开「自动备份」后重开应用 | 出现 `kof-auto-android.kofbak`，状态写回「已自动备份（10-31 13:23）」 |

单元测试：Android **168 条**全绿（新增 7 条：文件名往返、207 解析含大小写前缀与编码、
排序、路径校验、自动备份识别）；桌面 Rust **252 条**（新增 3 条：手机备份不被清理、
过期本机备份被清理、旧响应缺 `source` 仍按本机处理；另加 207 来源识别）。
桌面 UI 1032 条、i18n 658 条（100%）全过。

## 已知边界

- **统计不同步**：两端的 `StatsDay` 结构不同，且"手机使用时长"和"电脑使用时长"是两回事，
  合并会重复计数。统计仍是各设备本机的数据。
- 恢复时如果云端那份是**别人设的密码**加密的，需要在本机「备份密码」里填同一个；
  填错会明确报"密码不对"，不会当成文件损坏。
