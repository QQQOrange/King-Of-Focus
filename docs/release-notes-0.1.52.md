**三端统一的更新通道：桌面 / 安卓 / 插件各拿各的包，装错平台这种事从结构上堵死。**

以前桌面端"在 Release 里找一个 .exe"，安卓和插件根本没有更新链路。现在同一个 Release
里挂三种包，靠一份**更新清单**说清楚"哪个平台用哪个文件、多大、sha256 多少"。

### 更新清单（`King.Of.Focus-update.json`）
- 随 Release 上传，`platforms` 下每个平台一条：`version` / `kind` / `file` / `size` / `sha256`
- 客户端只读**写给自己的那一条**，读不到就明确说"这次发布没有你这个平台的包"，
  **不会回退去找别的平台的包**
- 清单由 `tools/release_meta.py` 按实际产物生成，不手写

### 三重匹配校验（三端同一套，错误码逐字相同）
1. **平台标识**：`windows-x64` / `android` / `chrome-extension`，编译期定死，用户改不了
2. **包类型**：桌面只收 exe/msi、安卓只收 apk、插件只收 zip/crx；包名必须是
   `King.Of.Focus-<版本>-<平台>.<扩展名>`，版本和平台都要与清单一致
3. **版本号**：必须比当前新，且与包名一致
4. 另外核 `size` 与 `sha256`：下载后逐字节比对，对不上就删文件并拒绝安装

### 失败时用户看到什么
- `E_PLATFORM_MISSING`：这次发布没有 Windows/Android/插件的包
- `E_TYPE_MISMATCH`：这是别的平台的安装包
- `E_NAME_MISMATCH` / `E_ASSET_MISSING` / `E_BAD_HASH`：清单与发布资产对不上
- 每条都带错误码，能直接对到 `docs/update-channels.md`

### 各端界面
- 桌面：关于页「自动更新」显示本机更新通道，下载前把校验来源写清楚
- 安卓（0.2.1）：设置 → 版本与更新：自动检查开关、检查间隔、立即检查、下载并安装、跳过此版本
- 插件（1.1.1）：弹窗「版本与更新」：当前版本、平台、自动检查、检查更新、下载新版本

### 发布前的一致性闸门
`python tools/release_meta.py check` 会拦下：版本号格式不对、清单与源码版本不一致、
产物缺失或命名不规范、大小/sha256 与清单不符、Release 缺某个平台的包。

测试：Rust 241、UI 1032、插件匹配器 47、插件更新校验 23、i18n 656/656、Android 61。
