# 0.1.101 / Android 0.6.0

这一版是对齐双端：把桌面已经修过、手机端没跟上的口径补上，再把"跨设备"这件事做成能看见、能点。

## 一、安卓端不再是"改了源码还发旧包"

`tools/release_meta.py` 的 `stage_android` 原来只是把现成的 APK 复制到 `dist/`。
改了 Kotlin 却忘了重新构建时，发出去的 Release 里装的是上一版的包——**版本号也没变**，
看起来一切正常，只有用户装完发现"这个修复怎么没生效"。

现在加了 mtime 闸门：`android/` 下的源码（含 `build.gradle.kts`、gradle 脚本）比 APK 新，
`release_meta.py build` 直接失败，并告诉你是哪个文件、差多久。

## 二、双端口径对齐（Android 0.6.0）

| 项 | 桌面 | 手机（本版修复） |
|---|---|---|
| 积分锁解锁期间算不算"自律生效中" | 0.1.97 起记为**未开启**（`stats::sample`） | `StatsTrack.on` 增加 `LockEngine.isUnlocked` 判定，与桌面一致 |
| 账本区间上限 | 366 天（`ledger::range`） | `LedgerStore.range` 现在也夹到 366 天——不夹的话一个超大区间会在主线程开几百万个文件，直接 ANR |

新增 5 条单测（`CrossDeviceParityTest`）：解锁窗口内 / 过期后 / 总开关关闭三种判定，加区间夹取与正常区间不被改短。

## 三、手机端的报告能存下来了

以前报告只能当场复制或分享，关掉页面就没了。现在：

- 「保存报告」把当前这份存到 `filesDir/reports/<日期>-<周期>.txt`（同一天同一周期覆盖，不堆重复）
- 「已保存（N）」打开列表：标题、保存时间、字数，每项可 **复制 / 分享 / 删除**
- 最多 60 份，超了自动删最旧的

## 四、手机端显示规则的配色

桌面端给规则配的颜色以前只藏在 `carry` 里：往返不丢，但手机上永远看不见，
同一条规则在两端的列表里长得不一样。现在 `Rule.color` 是真字段，列表左侧画色点
（只读，手机端没有调色板），回传桌面时原样写回。

## 五、桌面端「三端版本」与跨设备入口

- **关于页**新增「三端版本」卡片：桌面端（当前运行）、手机端、浏览器插件各自的版本 +
  「下载」按钮（直接打开该平台的 Release 资产链接）。
  版本来自**上次检查更新时缓存的清单**（`settings.update.platforms`），不会为它多打一次网络请求；
  没检查过就如实写"还没检查过"。
- **统计页的「另一台设备」横幅**补了三件事：多久没更新（≥3 天标红）、本机上次云端同步时间、
  「去云同步 ↗」直达入口。以前只有读数，用户想去同步还得自己找。

## 没有做的（说清楚，不含糊）

1. **手机端英文界面**：Android 的文案几乎全部内联在 Compose 里（10 个界面、上百条），
   不是加一个 `values-en` 就能解决的，需要先抽一层 `Loc`。这是独立一轮的工作量，
   硬做只能得到"一半英文一半中文"，比不做更糟。
2. **Android 网页拦截**：要 VPNService 或无障碍抓 URL，属高敏感权限，
   `android/README.md` 里本来就写明不在范围内。
3. **桌面 ↔ 手机实时推送**：没有推送通道；走云目录轮询的话延迟以分钟计，
   没有实用价值（真正的做法是自建服务端）。
4. **增量同步（只传变更）**：要做就得改备份格式与两端同步状态机，
   和"整份备份"并存还需要冲突策略——单开一版比塞进这版更稳。
