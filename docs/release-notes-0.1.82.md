# 0.1.82

这一版把"目标"从**一句话**变成**有结果的账**。对应的是那一批建议里的 A5：
把「专注 2 小时」换成「做完这套卷」。

## 一、上一段结束，总览直接问一句

段目标以前只有"写了什么"，没有"做成没有"。现在上一段一结束（6 小时内，
且写过目标），总览三件套下面会多一行：

```
上一段「写完登录页」    [做完了] [做了一半] [没做成]
```

点一下即记录，选中的那个变成实心；**再点一次就是撤销**（填错、或想重新判断）。
只回溯 6 小时——早上那一段到晚上还追着问，那不叫复盘，叫骚扰。

## 二、为什么不做"进度条 + 数量"

「背 40 个词」这类目标看似需要 `3/10` 这样的进度，但那会把这套软件变成一个小型
任务管理器，而它要给的是"这一段有没有真的做出东西"，不是又一个待办清单。
「做完这套卷」本来就是二元的；确实只做了一半，`partial` 这一档也够。
所以只有三档：做完 / 一半 / 没做成，**外加"还没答"**（空）。

## 三、完成率进了周复盘

周复盘第 3 题从"有几天写了目标"换成真正的成果账：

> 写了 **6** 个段目标：做完 **3**、做了一半 **1**、没做成 **1**、还没答 **1**
> → 「没做成 / 还没答的那几个，是目标定太大了，还是时间选得不对？」

如果没有没完成的，问题会换成「做完的那几个，凭什么做得完？」——这一问比表扬有用。

「分心事件」页的时段分组里也多了一个小标（绿色「做完了」/ 红色「没做成」），
让"原本要做什么 → 记了什么 → 做成没有"在一行里对得上。

## 四、顺手修掉一个会吃掉用户数据的测试

上一版为周复盘写的那个单测会真的写 `reviews.json`（就在用户数据目录里），
跑完还把文件删掉——等于每跑一次 `cargo test` 就把用户这周的复盘清空。
现在改成**先备份、跑完还原**。
