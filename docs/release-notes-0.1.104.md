# 0.1.104 — 分区重置（带快照与撤销）

调坏了某一类设置，以前只有两条路：一项项手动改回去，或者整份恢复备份（把规则、积分一起带走）。
现在多一条：**只重置那一块**。

## 可以重置什么

设置页最下面新增「分区重置」卡片，12 个分区：

| 分区 | 重置后 |
|---|---|
| 自律规则 | 回到出厂那条「自律时间」，自定义规则删除 |
| 自律时段 | 7×24 表与多套方案一并恢复默认 |
| 专注遮罩 | 透明度 / 跟随 / 点击穿透 / 热键 |
| 睡眠管理 | 睡眠时段与关机倒计时（默认关闭） |
| HUD 外观 | 停靠角 / 边距 / 透明度 |
| 激励语录 | 自定义语录与自定义来源清空，回到内置精选 |
| 阶段提醒 | 开关与提前量 |
| 分心事件 | 提醒间隔 / 上限 / 按钮位置 |
| 统计口径 | 保留天数与计闲规则（**不删已统计的数据**） |
| 浏览器插件 | 巡检 / 宽限 / 自定义浏览器与路径 |
| 云同步 | WebDAV 地址与凭据（本机备份不动） |
| 更新通道 | GitHub 令牌与跳过版本 |

**积分不在可重置范围内**：那是赚来的，不是设置。

## 三条安全线

1. **只动一块**：`reset::apply` 每个分支只碰自己那几个字段，整份配置的其它部分原样保留。
   六条单测逐个验证"重置 A 不影响 B"，`cargo test` 293 → **299**。
2. **先快照、可撤销**：重置前写 `config.pre-reset-<时间>-<分区>.json`，卡片上直接显示
   「上次重置：某分区 · 时间」和「撤销上次重置」按钮；快照留最近 5 份。
   撤销时**不会**把积分和"另一台设备的统计"回滚——那不是设置，回滚等于没收这段时间赚的分。
3. **不能当绕过用**：规则 / 时段 / 睡眠被重置，等于削弱当前这一轮自律。所以重置和撤销
   都要过 `guard::config_replace_blocked` 这道闸（和"整份覆盖配置"同一套判据），
   自律时段或固化中会被拒绝并说明原因。

## 界面上的取舍

没做成"12 个并排的红色恢复按钮"——重置是破坏性操作，界面不该给 12 个手滑的机会。
现在是一排分区小胶囊（选中高亮）+ 一句这个分区会重置掉什么的说明 + 一个按钮，执行前还要过确认框。

顺手修的两处：

- 状态行加了 3 秒超时。后端卡住时那行不能永远停在「读取中…」，现在会显示
  「状态读取失败，不影响重置本身」。
- 这些文字是 `textContent` 直接赋值的，不走 DOM 翻译扫描，所以显式过了 `I.t()`——
  英文界面下不会露出中文。

## 顺带记一笔踩坑

给 12 个分区名补英文时，我重复定义了「自律规则 / 自律时段 / 专注遮罩 / 浏览器插件」等
导航里已有的词条，后写的覆盖了先写的，导航文字当场从 Rules 变成 Discipline rules——
被 harness 的「英文界面没有残留中文」和「规则页标题也翻了」两条断言抓住。
已改成复用导航词条，并在字典里留注释说明**不要重复定义**。
