# v0.1.70 / Android 0.4.6 — 一份备份，两端同构

> 主题：把"跨设备备份"从"两端都能读"提升到"两端写得一模一样"，
> 并彻底消灭"只有生成备份的那台设备能打开"的文件。

## 一、备份只有一个格式

以前桌面端的「立即备份」和云端备份在**没设密码**时走 Windows DPAPI：
文件跟当前账户绑定，换台电脑重装、或者拿手机去恢复，只会看到"文件损坏"。
这就是典型的「只能由生成备份的设备读取」。

现在写入路径统一成一条：

| 情况 | 文件形态 |
|---|---|
| 设了备份密码 | `kofEnc:3`（PBKDF2-HMAC-SHA256 600000 轮 + AES-256-GCM） |
| 没设密码 | 明文 JSON（生成时界面会提醒） |

- 本地备份、云端备份、手动导出**产出的是同一种文件**，拿哪台设备都能恢复。
- 老备份（`kofEnc:1` Argon2id / `kofEnc:2` DPAPI）仍然读得懂，只是不再写。
- 不认来源：`source` / `device` 只在界面上显示"这份来自哪台机器"，
  读写路径上一个分支都不看它。

## 二、字段逐键对齐

为了"两个平台导出的文件结构完全一致"，这次把几处历史遗留的偏差都抹平了：

- **规则**：手机端导出的规则对象以前只有 `id/name/enabled/mode/hard/apps/sites/exceptions`，
  现在补齐 `schedule / lock / color / extraProtected / brk / autolaunch`，
  连 `apps[].id` 都写——否则两端的"同一种文件"只是名字相同。
- **积分**：文档只放两端都有的四项 `balance / totalEarned / unlockUntil / sleepUnlockUntil`；
  桌面端的"今日解锁次数"是本机记账，不再跟着备份跑到另一台机器上算错。
- **提醒**：只放两端都有的四项；桌面的"提醒时拉窗口到前台"不再进出文档。
- **语言 / 配色**：手机端没有这两个概念，导出时写空串（=「没意见」）。
  以前它硬写 `zh-CN` / `system`，于是桌面用户把界面调成英文 + 深色之后，
  恢复一次手机备份就被"一键还原"。
- **休息上限 `defCap`**：始终写出（0 也写）。省略会让另一端分不清"没有上限"和"没这个键"。

## 三、怎么防止两端再次跑偏

只靠"能读"是发现不了字段漂移的（少写一个键，读的时候会被默认值兜住）。
新增三层机器校验：

1. `tools/fixtures/portable-canon.json` —— 两端共用的参考文档（桌面端生成）。
2. `tools/fixtures/portable-shape.txt` —— 它的**字段签名**（每行一个 `路径:类型`，94 行）。
   - 桌面端 `export_shape_matches_reference`：自己导出的必须量出这份签名。
   - 手机端 `exportShapeMatchesReference`：把参考文档落到手机配置再导出，也必须量出这份签名。
3. `node tools/check_portable.js` —— 检查 `KOF` / `FORMAT` / `SCHEMA` 在两端源码里逐字相同、
   签名与参考文档对得上、所有样例的键与类型合法。

任何一个字段被单方面改动，对应的测试立刻红。

## 四、版本管理

- `schema` 只在**破坏性**改动时 +1（改语义 / 删字段 / 改类型）；**加字段不升**。
- 读端遇到 `schema` 比自己新，直接拒绝并提示升级——不"猜着读一半"。
- `kofEnc` 是加密方式编号，独立于 `schema`；目前只写 3。
- 老格式（没有 `kof` 标记、载荷是整份 `Config`）仍然识别，走"整份覆盖"的老语义。

详见 `docs/backup-format.md`。

## 五、顺手修的

- 「备份密码」留空时的占位文案从"用本机 DPAPI 加密"改为"明文备份（两端都能读）"，
  并同步了帮助页与提示语（中英双语）。
- 恢复备份不再清零本机的"今日用了几次积分解锁"。
- 手机端恢复备份会带回 `sleepUnlockUntil`：以前手机恢复桌面备份会把桌面已经
  花积分买断的睡眠时段重新锁上。
