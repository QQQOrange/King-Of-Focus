# v0.1.58 · 安卓端「使用统计」按桌面端口径重做

安卓 **0.3.5**。桌面端功能不变，版本号跟着发布走。

手机的统计以前只有一个总数：每 15 秒记一笔固定的 15 秒，熄屏不计，没有"自律时段内 / 时段外"的区分，
也回答不了"几点到几点在用它"。这一版把桌面端 `stats.rs` 那套口径整体搬过来。

## 一、双轨：自律生效中 / 时段外

- 数据一天两份：`on`（自律生效中）与 `off`（其余时间），完全隔离。
- 「生效中」的判定**与拦截同一个口径**：规则生效 || 时段专注 || 锁机。
  早期手机端只判规则，于是"只排了时段、没配规则"的时间全被记到「时段外」——
  而这恰好是这套工具唯一值得看的那个数字。
- 统计页三档：**自律时段内 / 时段外 / 汇总**（汇总 = 两轨相加，不做加权，与桌面同义）。

## 二、记账方式

| | 以前 | 现在（与桌面一致） |
|---|---|---|
| 结算 | 每 15 拍记固定 15 秒 | **每秒结算一次**，按真实经过的秒数 |
| 跨整点 | 全记到当前小时 | 按小时边界切开 |
| 跨天 | 可能串天 | 切开，23:59:58 的两秒不进第二天 |
| 服务被冻结后补账 | 无上限 | 最多按 5 分钟（那段时间人不在） |

## 三、什么算"在用"

- **熄屏、锁屏、停在桌面或本应用界面**：一律不计，并封口当前连续段。
  桌面端用 `GetLastInputInfo` 判断人还在不在，Android 没有等价 API——
  所以默认「亮屏 + 未锁屏」即算；设置里关掉「只看屏幕亮着」后，
  还要求 60 秒内有过无障碍事件（**没授权限会如实说明这项不生效**，不假装生效）。
- 实测：熄屏 120 秒，统计只增加了 3 秒（那 3 秒是熄屏前亮屏又用了一会儿）。

## 四、连续使用段（spans）

小时桶回答"这一小时用了多久"，回答不了"几点到几点在用"。
现在每个应用都带连续使用段，统计页点开某个应用就能看到：

```
共 1 段，合计约 3 分钟
10-31   11:29–11:32   3 分
```

段按分钟取整（与桌面 `Span` 完全一致），所以合计写"约"。

## 五、统计不再依赖自律开关

以前关掉自律总开关，守护服务直接停掉 → 统计整条停摆，「时段外」永远是空的。
现在 `shouldRun = 自律开 || 统计开`，两个都关才停。常驻通知也会如实写
「自律已关闭 · 正在记录使用时长」。

## 六、其余对齐

- **保留天数**：默认 400 天（桌面 `retention_days` 同值，可调；以前写死 90 天）。
- **周报**：累计 / 日均 / 生效中占比 / 最长的一天 / 用得最多 / 峰值小时，跟着所选轨走。
- **老数据兼容**：分轨之前的 `apps` 格式读进来落到「时段外」（那时没有自律状态可查），
  明细里注明"这一段没有分段数据"，不假装有。
- 顺手修掉一个会让统计永远为 0 的隐患：统计目录若是被外部删掉，写入会一直静默失败；
  现在每次写盘前补建目录。

## 验证（AVD kof35）

| 场景 | 结果 |
|---|---|
| 自律开 + 周六 11 点在时段内，用设置页 70 秒 | `on` 轨 +58 秒，hour[11]，段 684–686 |
| 自律关 + 统计开，同样操作 | `off` 轨 +58 秒；`on` 轨不动 |
| 熄屏 120 秒 | 总秒数只 +3（熄屏前后亮屏那会儿） |
| 统计页三档切换 | 自律时段内 0 秒 + 空态提示；时段外 1 分钟；汇总两者相加 |
| 点开应用看明细 | `共 1 段 / 10-31 / 11:29–11:32 / 3 分` |
| 未封口的段 | 落盘时也写进去，重启进程后仍在 |
| 老格式日文件 | 读进「时段外」，不崩、明细注明无段 |

单测：Android **135 条**全绿（新增 13 条统计用例：跨整点/跨天切分、补账上限、
双轨隔离、落盘往返、段的合并与断开、老格式、坏文件、保留天数、双轨判定）；
桌面 Rust 241 条、UI 1032、i18n 656 全过（桌面代码未改）。

## 没搬的

桌面端的「自动生成日报/周报/月报/年报 + 自定义周期」和「周/月日历 + 饼图」
是桌面布局才撑得开的东西，手机端仍是手动生成文本报告 + 直方图。
数据层已经按天存好，以后要做只是界面工作。
