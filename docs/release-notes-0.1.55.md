# v0.1.55 · 安卓自律四修：白名单真拦、过期列锁编辑、逐日清空、遮罩单一名单

桌面端功能不变，版本号跟着发布走；安卓 **0.3.2**。

## 一、白名单模式：从"只回桌面"到"真退出"

之前命中规则只做了两件事：回桌面 + 一条通知。看起来"没执行"，原因有三层：

1. 通知在没授通知权限时会被系统丢弃，用户什么都看不到；
2. 应用只是被赶到后台，桌面图标一点又回来了；
3. 白名单名单和锁机名单是两份，容易配成自相矛盾。

现在：

- 命中白名单规则且**有 Shizuku** → 先回桌面，再 `am force-stop <pkg>` 把它真关掉；
- 没有 Shizuku → 回桌面 + 高优先级通知（Android 不允许一个应用结束另一个应用，这是硬限制）；
- 去重窗口从 5 秒收紧到 3 秒，"立刻退出"更接近字面意思；
- 规则页顶部新增一行状态：`总开关关着` / `不在时段内` / `番茄休息段` / `积分解锁中` / `生效中`。
  "配了不生效"绝大多数就是这几种，现在不用猜。

## 二、时段：今天之前的星期不可编辑

网格按周循环，但"这一周里已经过去的星期"不允许再改（周六时周一至周五灰掉并标注「锁」）。

- **界面**：锁住的列盖一层底色、表头标「锁」，拖动不会涂色，点表头只给原因；
- **数据层**：所有写入都过 `ScheduleRules.paint / paintAll`，被锁的日子原样返回。
  只把界面点灰是不够的——换个入口就绕过去了；
- 原有计划**照常生效**，只是不能改；每周一自动解锁。

## 三、每天一键清空（带二次确认）

点表头 → 「全选」/「清空这一天」。清空会再问一次"这一步不能撤销"，
确认后整天计划清掉。底部的「今天清空」也走同一套确认。

## 四、锁机遮罩：补齐展示，名单收敛成一份

遮罩本身是好的（全屏 Activity、返回键无效、点白名单应用后返回仍在、暂停/停止立即退场），
这一版补的是"两处配置打架"：

- 遮罩的「允许的应用」= `GuardEngine.allowedPackages(cfg)`，也就是**规则页里白名单规则的并集**；
- 删掉设置页里的第二份选择器，改成只读说明；老配置的 `lockAllow` 在 `normalize` 里
  自动并成一条名为「允许的应用」的白名单规则，**不丢用户勾过的应用**；
- 遮罩判定、拦截判定、设置页展示读的都是这一份。

## 验证（AVD kof35，设备时间 2026-10-31 周六）

| 场景 | 结果 |
|---|---|
| 白名单只放 settings，打开通讯录 | 5 秒内前台变成 launcher（被送回桌面） |
| 打开设置（在白名单） | 停留，未被拦 |
| 开锁机 | 前台是 `.ui.LockActivity`，显示「允许的应用（1）」 |
| 遮罩上按返回键 | 仍是 LockActivity（不退出） |
| 遮罩 → 点 Settings → 返回 | 回到 LockActivity |
| 老配置（只有 lockAllow、没有规则） | 遮罩显示「允许的应用（1）」，说明已迁移 |
| 周六拖周一列 09:00→10:00 | 计划无变化（锁住） |
| 周六拖周六列 | 正常写入，15 分钟精度（from 45/to 45） |
| 周一表头 | 只有说明，无「全选/清空」（锁住） |
| 周六表头 → 清空这一天 → 确认 | 当天计划清零 |
| 规则页 | 显示「生效中：规则正在按「时段」执行」 |

单测：Android **105 条**全绿（新增 12：`GuardEngineTest` 7 条覆盖白名单联动与老配置迁移、
`ScheduleRulesTest` 5 条覆盖可编辑范围与写入拦截）。

## 仍然做不到的

- **没有 Shizuku 时无法结束别的应用**：只能回桌面 + 通知。这是 Android 的沙箱规则，
  不是实现偷懒；装 Shizuku 并授权后行为会升级成真正的 `force-stop`。
- **锁机遮罩依赖「在其他应用上层显示」**：缺权限时后台拉不起页面，会发一条
  「锁机没生效」的通知，而不是假装在管。
