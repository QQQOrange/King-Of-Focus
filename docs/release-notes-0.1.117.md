# 0.1.117 / Android 0.7.1 — 手机端英文界面：机制先立起来，导航与总览已覆盖

手机端一直是纯中文：文案全部内联在 Compose 里，共 **1657 条唯一中文字面量**。
抽语言层不难，难的是逐条翻译——那是一次纯人工的翻译工程。这一版先做**机制**，
并完成第一块屏幕，剩下的按屏幕往里填。

## 一、`Loc`：查不到就回中文，永远不会显示 key

```kotlin
Loc.t("总览")        // en → "Overview"；没有译文 → 原样返回中文
Loc.isEn             // 带插值的句子用它分支，不必把 Kotlin 模板拆成格式串
```

- 语言**跟随系统**（`Locale.getDefault()`）：英文系统用英文，中文系统一个字都不变；
- **不引入任何配置字段**，因此不碰跨端备份格式（`settings.lang` 依旧留空，
  手机备份不会把桌面调好的语言改掉）；
- `Loc.init()` 在 `Application.onCreate` 里、`Store.init` 之前调用——晚一步会先闪一帧中文。

## 二、第一块屏幕：底部导航 + 总览

`App.kt` 的 60 处纯中文字面量已包成 `Loc.t(…)`，5 处带插值的句子改成 `Loc.isEn` 分支
（保留 Kotlin 模板，不拼格式串）。词典 53 条，覆盖：底部 5 个 Tab、总览的状态卡、
今日进度、试用入口、限制能力/权限那一段、悬浮窗权限说明。

## 三、加了两条闸门（这才是关键）

`LocCoverageTest` 直接从源码里抠出所有 `Loc.t("…")`，和词典对一遍：

1. **每个 `Loc.t` 都必须有译文** —— 漏一条就红。
   这条闸门存在的理由：`Loc.t` 查不到时**回退中文，不崩、不显示 key**，
   运行时完全看不出来；英文用户只会看到一句中文夹在英文里，而那只有他自己会发现。
2. **词典里不能堆死条目**（超过 15 条就红），防止有人只加不删。

写这条测试时踩了个小坑：Kotlin 编译期会把 `\n` 变成真换行，而测试是从**源码文本**
抓 key 的。`"…失效。\n\n"` 这种句子源里是反斜杠 n、词典里是真换行，不做还原就永远对不上。

## 四、覆盖率（说实话）

- 已英文化：底部导航、总览页（**约 5% 的界面文案**）
- 未英文化：时段、规则、统计、设置、锁机页、通知文案等（其余 95%）

对英文用户来说，现在打开是"英文导航 + 中文正文"。**这不是完成态**，
但机制和闸门都在，后面每一屏都是"包 `Loc.t` + 补译文"的机械活，可以一屏一屏推。
