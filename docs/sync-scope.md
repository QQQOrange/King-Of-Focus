# 云同步：数据范围、触发时机与冲突处理

> 一句话：**规则、自律时段、积分、提醒、以及"另一台设备用了多久"，一起走同一条 `.kofbak` 通道。**
> 原始统计日文件不互传（两端结构不同），只传各端算好的**摘要**。

---

## 一、数据范围

| 段 | 内容 | 是否同步 | 说明 |
|---|---|---|---|
| `rules` | 规则（黑白名单、网站名单、启用的时间表、绑定的自动启动） | ✅ 全量 | 覆盖=整体替换；合并=只加不改 |
| `clock` | 自律时段：`profiles[]`（7×24 排班、`defWork/defBrk/defCap`、`bound` 绑定分组）、`active`、`granularity`、总开关 `enabled` | ✅ 全量 | **这就是"当日日程安排"**：电脑上排好的时段，手机上同步后一模一样，包括 15 分钟刻度和"每小时休息上限" |
| `points` | 积分余额、累计获得、解锁到期时间 | ✅ | 覆盖取文件值；合并取较大值（不累加，否则来回导入能刷分） |
| `settings` | 语言、主题、提醒（专注/休息提前量、休息是否提醒） | ✅ | 桌面专属的"提醒时拉窗口到前台"保留本机 |
| `stats` | **统计摘要**：每天 `total`（总时长）、`on`（自律时段时长）、`top`（前 3 个应用） | ✅ 摘要 | 30 天，约 3 KB。**不含**逐应用逐小时的原始数据 |
| 原始统计日文件 | 桌面 `acc/hours/spans`、手机 24 小时桶 | ❌ | 两端结构不同，互传读不懂；摘要已经能回答"另一台用了多久" |
| 密码 / 令牌 | WebDAV 口令、备份口令、更新令牌 | ❌ | 明文上传等于把凭据交给网盘（`sync::payload` 里有剥离） |

### 已知边界（不是 bug，是两端应用标识不同）

| 项 | 现象 | 原因 / 处理 |
|---|---|---|
| 规则里的**应用条目** | 桌面用 exe 路径（`C:/Tools/vscode.exe`），手机用包名（`com.tencent.mm`） | 手机端把桌面条目放进 `foreign`（桌面专属），原样带回桌面，**不会**硬塞进手机的包名名单。手机要在自己设备上生效，得在手机上加一次包名 |
| 规则里的**网站条目** | 桌面靠浏览器插件拦，手机没有插件 | 条目照样带过来（保留在规则里），手机上不生效 |
| 自动启动项 | 桌面专属（进程/网址/文件） | 跟着规则走，手机上忽略 |
| 统计**原始数据** | 不互传 | 见下一节 |

> 一句话：**结构性配置（规则名单、时段、积分、提醒）完全一致；只有"怎么识别一个应用"这一层
> 天生跨不了平台。** 这一点在同步结果里不隐藏：手机端规则卡片会标出"桌面专属 N 条"。

### 为什么统计只传摘要

1. **结构不同**：桌面按 `Acc{label,secs,hours[24],spans[]}`，手机按 `Map<包名, Acc{secs,hourBuckets}>`，
   硬塞会算错或丢字段。
2. **不该相加**：手机 3 小时 + 电脑 8 小时 = 11 小时，既不是"我用了多久"也不是某台设备的用量。
   所以摘要**分设备存**，界面上单独一行（"另一台设备 · 手机（Pixel）：最近 7 天总 6 小时 20 分 · 自律 2 小时 10 分"）。
3. **文件大小**：摘要 30 天约 3 KB，原始数据动辄几十 MB —— 后者放进备份会让每次同步都变慢。

## 二、触发时机

| 场景 | 谁触发 | 传什么 |
|---|---|---|
| 桌面「立即同步」 | 用户点击 | `king-of-focus.json`（配置）**+ 一份 `.kofbak`**（带规则/时段/统计摘要） |
| 桌面自动同步（默认 30 分钟） | 后台线程，`enabled && auto` 时 | 同上（走 `smart`：云端新就下载、本机新就上传） |
| 桌面「上传本机 → 云端」 | 用户点击 | 配置 + `.kofbak` |
| 桌面「备份 → 上传当前配置」 | 用户点击 | 仅 `.kofbak` |
| 桌面备份恢复 | 用户点击「恢复」 | 应用 `.kofbak` 里的规则/时段/积分/摘要 |
| 手机「立即同步」 | 用户点击 | 比较云端最新 `.kofbak` 与本机 `updatedAt`：云端新→覆盖本机；本机新→上传 |
| 手机「上传本机」 | 用户点击 | 一份 `.kofbak`（带摘要） |
| 手机「恢复云端最新」 | 用户点击 | 选合并/覆盖应用 |
| 手机自动备份（回前台，10 分钟节流） | `CloudAuto` | `kof-auto-android.kofbak`（固定名覆盖） |

> **关键点**：手机只认 `.kofbak`。所以桌面「立即同步」现在会**顺带传一份 `.kofbak`**，
> 否则手机上点同步看不到桌面的新改动（以前就是这样：桌面传的是它自己的 JSON，手机读不懂）。
> 附带备份失败不影响配置上传，结果字符串里会注明。

## 三、冲突处理

### 3.1 配置（规则/时段/积分/提醒）：last-write-wins

比 `updatedAt`（unix 秒）：

- 云端 `updatedAt > 本机 + 2` → 下载覆盖；
- 本机 `> 云端 + 2` → 上传；
- 差 2 秒内 → 视为同一版本，不做任何事（避免来回抖）。

### 3.2 两种应用模式（用户点恢复到某个文件时选）

| | 覆盖 | 合并 |
|---|---|---|
| 规则 | 整体替换 | 只加：同 id 或同内容跳过；同名不同内容改名并列并计冲突 |
| 时段 | 整体替换（含方案列表） | **只补本机空着的小时**，已选中的一小时都不改 |
| 积分 | 取文件值 | 取两边较大值 |
| 设置 | 跟随文件 | 不动（合并的承诺是"只会多、不会变"） |
| 统计摘要 | 收（若更新） | 收（若更新） |

### 3.3 统计摘要：只进不退

- 空摘要不收（对方刚装、还没数据）；
- `at` 不比本机已有的大就不收（旧摘要不能把新数字盖回去）；
- **自己导出的不收**（同一台机器恢复自己的备份，不该在"另一台设备"里看到自己）。

摘要不进 `updatedAt` 的比较链 —— 它是"附件"，不是"配置"。所以收摘要本身不会触发一次"配置被覆盖"。

## 四、验收（可逐条对照）

| 场景 | 期望 |
|---|---|
| 电脑排好周一 09:00–12:00、25/5、休息上限 15 分，手机同步 | 手机「时段」页周一 09:00–12:00 完全一致，节奏 25/5、上限 15 都在 |
| 电脑新建一条白名单规则并绑定到该方案，手机同步 | 手机规则列表出现同一条，`bound` 也指到同一方案 |
| 电脑改积分到 777，手机合并同步 | 手机积分 ≥ 777（取较大值，不会变小） |
| 手机今天用了 2 小时、电脑 5 小时，两端互相同步后 | 两端各自的本机统计不变；统计页多出"另一台设备"一行，数字分别正确 |
| 同一份摘要同步两次 | 第二次不产生变化（`at` 没变大） |
| 手机恢复自己昨天导出的备份 | **不会**多出"另一台设备（手机）"卡片 |
| 云端没有 `.kofbak`、只有 `king-focus.json` | 手机列表为空并提示"云端还没有备份"（不误删、不误读） |
| 桌面「立即同步」被网络中断（备份那一步失败） | 配置已上传，结果里注明「附带备份未上传：…」，不当作整体失败 |
| 桌面规则含 exe 路径，手机同步后 | 规则本身在，条目落在"桌面专属"里（`foreign`），手机包名名单为空——不会误拦手机上的同名应用 |
| 桌面「立即同步」后，手机立刻同步 | 手机能看到并拉取那份新 `.kofbak`（桌面同步会顺带传一份） |

自动化断言：
- Rust `portable::tests`（stats 采纳/旧的不覆盖/自己导出的不收/空的不收/合并不动规则）；
- Android `PeerStatsTest`（5 条：覆盖收下、合并收下、旧的不覆盖、空的不收、无 stats 段保留）；
- Android `PortableTest`（规则/时段/方案绑定的往返）。
