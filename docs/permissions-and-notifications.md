# 权限、通知与降级清单（Android）

这份清单是**给用户看的**，也是代码里 `core/Permissions.kt` 的可读版本。
两者内容一致：应用内「总览 → 权限与能力」里展开每一项，看到的就是这里的一行行。

一句话原则：**不需要的权限不申请**；没有它也能用的功能，就把降级方案写清楚，
而不是先让用户开、再默默失效。

---

## 一、权限

> 「拒绝」= 弹过窗被拒，还能再弹；「永久拒绝」= 系统不再弹窗，只能去设置里手动开。
> 应用内会分别显示「已拒绝 N 次」和「已被永久拒绝」，两种情况给的动作不一样。

### 1. 应用列表（`QUERY_ALL_PACKAGES`）

| 项 | 内容 |
|---|---|
| 用途 | 应用选择器要能列出手机上所有应用，才能把它们加进自律规则。否则只能看到「已经打开过的」那几个。 |
| 申请时机 | 安装即得，不需要申请。第一次打开「自律规则 → 添加应用」时使用。 |
| 申请方式 | 清单声明，系统安装时自动授予。 |
| 拒绝后 | 用户无法拒绝；极少数 ROM / 商店裁剪版会限制可见性。 |
| 降级 | 仍可按包名手动添加；**已配置的规则照常生效**（判定不需要这个权限）。 |
| 重新授权 | 没有单独开关；列表明显不全时，去应用信息里看是否被「应用权限管理」限制。 |

### 2. 通知（`POST_NOTIFICATIONS`，Android 13+ 运行时权限）

| 项 | 内容 |
|---|---|
| 用途 | 四类通知全靠它：常驻状态（含今日进度）、阶段结束前提醒、任务完成、当日使用汇总。 |
| 申请时机 | **第一次开启「自律总开关」时**——此时才有内容可发。也可在「设置 → 通知 → 去开启通知」手动申请。启动就弹的话用户还不知道这应用做什么，大概率直接拒绝。 |
| 申请方式 | 系统运行时弹窗（Android 13+）；更早版本安装即得。 |
| 拒绝后 | 守护仍在跑，但**四类通知都不出现**；前台服务在通知栏被折叠成「应用在后台运行」。应用内总览页与设置页都会显示「通知被关：…统计与拦截仍照常工作」。 |
| 降级 | 应用内照常显示状态与进度；统计、拦截、锁机**都不依赖通知**。 |
| 重新授权 | 「去开启」跳到本应用的通知设置。**永久拒绝**时不再弹窗（弹了也不会出现），直接跳设置。授权回来后 `notifBlocked` 自动清掉。 |

### 3. 照片和视频（`READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO`）

| 项 | 内容 |
|---|---|
| 用途 | **本应用不需要。** 备份走系统文件选择器（SAF），报表是文本，锁机背景是纯色，没有任何读取相册的场景。 |
| 申请时机 | 不申请。将来若做「锁机背景用自己选的照片」或「统计图存到相册」，才在用户点「选择照片」的那一刻申请。 |
| 申请方式 | 不申请。（真要加：运行时弹窗，且只在该操作时弹。） |
| 拒绝后 | 无影响——没有功能依赖它。 |
| 降级 | — |
| 重新授权 | — |

> 为什么写进清单却不申请：为了清单好看去要一个读相册的权限，既过不了商店审核，也是在骗用户。
> 这里如实标成「不需要」，应用内也显示灰色「不需要」而不是红色「缺失」。

### 4. 在其他应用上层显示（`SYSTEM_ALERT_WINDOW`）

| 项 | 内容 |
|---|---|
| 用途 | 锁机时把整屏遮罩盖到别的应用上面。Android 10+ 还要求它才能在后台拉起界面（BAL 限制）。 |
| 申请时机 | 第一次开启「锁机」时；以及锁机生效但遮罩没出现时（会弹一条可点开的提醒）。 |
| 申请方式 | 跳系统设置页「显示在其他应用上层」，用户手动打开。 |
| 拒绝后 | **锁机不生效**：到点只会回桌面 + 一条通知，盖不住屏幕；「强制模式」也因此不可用。 |
| 降级 | 拦截规则仍靠「回桌面 + 通知」生效；锁机降级为「提醒你该休息了」。 |
| 重新授权 | 「去开启」跳到本应用的悬浮窗设置；也可走系统设置 → 应用 → 特殊权限。 |

### 5. 使用情况访问（`PACKAGE_USAGE_STATS`）

| 项 | 内容 |
|---|---|
| 用途 | 读取「当前前台是哪个应用」（拦截的判定依据），以及按应用统计使用时长。这是 Android 上唯一不需要 root 的公开通道。 |
| 申请时机 | 第一次开启「记录使用时长」或「自律总开关」时；统计页顶部也会提示。 |
| 申请方式 | 跳系统设置页「使用情况访问」→ 找到本应用 → 允许。**没有运行时弹窗。** |
| 拒绝后 | **统计完全停止**（不采样、不写盘）；拦截只能靠无障碍，没有无障碍时等于什么都拦不住。 |
| 降级 | 只有无障碍时仍能识别前台并拦截，但统计不到时长；页面明确写「统计已暂停」，不会显示一片 0 让你以为今天没用手机。 |
| 重新授权 | 统计页顶部横幅或设置页「去授予」。**被回收时**（清理软件 / 系统更新）服务会推一条「使用情况访问被收回了」，点击回到本应用重新授予。 |

### 6. Shizuku（`moe.shizuku.manager.permission.API_V23`）

| 项 | 内容 |
|---|---|
| 用途 | 借 ADB 级 shell 权限做无障碍做不到的事：更准地读前台、真正结束违规应用（`am force-stop`）、把被关掉的无障碍重新打开、阻止在设置里强制停止本应用。 |
| 申请时机 | 用户主动点「连接 Shizuku」时；**不会自动申请**。 |
| 申请方式 | 先安装 Shizuku 并用无线调试启动它，再在本应用里授权（Shizuku 自己的弹窗）。 |
| 拒绝后 | 降级到无障碍 / 使用情况：拦截只能「回桌面 + 通知」，锁机需要悬浮窗，「强制模式」无法启用。 |
| 降级 | **完整应用不依赖 Shizuku**：没有它也能用，只是拦得没那么硬。能力等级显示「增强」而不是「完整」。 |
| 重新授权 | 「连接」会重新拉起 Shizuku 授权；已授权但没连上（Shizuku 被系统停掉）会提示「重新打开它」。 |

### 7. 无障碍服务（既有能力，一并列出）

| 项 | 内容 |
|---|---|
| 用途 | 切换应用的那一刻就知道前台是谁（比 1 秒轮询准），并且不受后台限制地回桌面。 |
| 申请时机 | 第一次开启「应用拦截」或「锁机」时；能力不足时总览页会提示。 |
| 申请方式 | 跳系统设置页「无障碍」→ 找到 King Of Focus → 打开。 |
| 拒绝后 | 前台识别退化为 1 秒轮询（需要「使用情况访问」），回桌面需要悬浮窗或 Shizuku。 |
| 降级 | 有「使用情况访问」时仍能拦截，只是慢一拍；锁机靠悬浮窗。 |
| 重新授权 | 「去开启」跳到无障碍设置；部分 ROM 重启后会关掉，Shizuku 在的话会自动帮你打开。 |

### 能力等级（四档，由上面几项组合决定）

| 等级 | 需要 | 能做什么 |
|---|---|---|
| 完整 | 无障碍 + Shizuku | 看得见、盖得住、设置里也停不掉 |
| 增强 | 无障碍 | 看得见盖得住，但设置里还能强制停止 |
| 基础 | 使用情况访问 + 悬浮窗 | 每秒轮询 + 遮罩 |
| 未生效 | 都不满足 | 只能记录（且统计也不准） |

## 二、通知

四类通知分属四个渠道，**系统设置里可以按渠道单独关**（比应用内开关更彻底）：
`自律守护` / `阶段提醒` / `任务完成` / `每日使用汇总`。

| 通知 | 触发条件 | 展示样式 | 更新频率 | 可关闭 / 可调 |
|---|---|---|---|---|
| **常驻状态** | 自律或统计任一开启时一直存在 | 低优先级、不可划掉、静默；标题「King Of Focus · 自律中/锁机中/睡眠中」，正文「专注中 · 00:21 · 今日 0/60 分」，副标题「今日自律 0/60 分」，带进度条 | 每秒刷新正文（剩余时间）；今日进度 30 秒一算 | 关掉「常驻状态显示今日进度」只留当前状态；彻底关掉=停止守护（系统层面） |
| **阶段结束前提醒** | 专注/休息剩余时间降到阈值（默认专注 5 分钟、休息 2 分钟） | 高优先级、会响；标题「阶段提醒」，正文「本轮专注还剩 5 分钟，坚持一下」 | 每个阶段**只响一次**（剩余时间跳大即视为新阶段） | 两个阈值都能调（0 = 不提醒）；「休息也提醒」可单独关 |
| **任务完成** | **阶段切换那一刻**：专注→休息、休息→专注 | 默认优先级、可划掉；标题「专注完成」/「休息结束」，正文带休息分钟数或「开始下一轮专注」+「今日已自律 X/Y 分」 | 每次切换一条，固定 id 覆盖上一条 | 独立开关「任务完成通知」。**刚启动或刚进时段不算完成**，不会误报 |
| **当日使用汇总** | 每天到点（默认 **22:00**）+ 当天**确实有记录** | 默认优先级、可划掉、支持展开（BigText）；标题「今日使用 3 小时 12 分」，正文「自律时段内 48 分（25%） · 用得最多：微信、Chrome」 | 每天最多一条；**发了才记账**，跨天自动重置 | 独立开关 + 汇总时间可调（0–23 点） |

### 几个刻意的取舍

- **没数据不发**：一天没怎么碰手机，22 点不该被打扰。到点时若还没有记录，会继续等——**不记账**，
  这样用户 22:30 才开始用手机，也还能收到当天的汇总。
- **先记账再发 / 发完才记账**：发通知失败（渠道被关）也算「发过了」，避免每拍重试刷屏；
  但「没数据」这种没发的情况不记账。
- **完成通知只在阶段边界发**：把「专注段被手动关掉」「切方案」也当完成会误报，所以不做。
- **常驻进度只在有计划时显示**：`0/0 分` 比不显示更让人困惑。

## 三、与代码的对应

| 内容 | 位置 |
|---|---|
| 权限四要素与状态判定 | `core/Permissions.kt`（唯一数据源） |
| 通知判定（完成 / 汇总 / 进度） | `core/NotifyPlan.kt`（纯函数，有单测） |
| 通知渠道与发送 | `service/GuardService.kt` |
| 通知权限申请与结果回写 | `ui/PermUi.kt` |
| 界面展示 | 总览页「权限与能力」、设置页「通知」 |
