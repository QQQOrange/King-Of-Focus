# 休息上限、时段块、锁机提醒与应用限制（0.4.0）

这份文档是**行为说明 + 验收清单**：写清楚每条规则在什么条件下成立、边界在哪，
以及怎么验证它成立。代码里的注释是给改代码的人看的，这里是给"要确认它到底怎么工作"的人看的。

两端共用同一套口径的部分会标 **【两端一致】**；只在一端实现或平台差异的部分标
**【Android】/【PC】** 并说明原因。

## 1. 累计休息上限（学习 N + 休息 M）【两端一致】

### 口径

- 设置项：`每小时休息上限`，单位分钟，**0 = 不限**（默认，行为与 0.3.x 完全一致）。
- 位置：Android「时段 → 番茄节奏」；PC「自律时段 → 通用时长」。
- 存储：方案级（`Config.defCap` / `ClockProfile.def_cap`），随方案走，也会随 `.kofbak` 备份跨端。

### 规则

以整点为相位锚点，一小时里第 `k` 轮休息：

| 条件 | 结果 |
|---|---|
| `cap = 0` | 每轮休息都足额（旧行为） |
| `cap ≥ 本轮已休 + brk` | 本轮足额 |
| `cap < 本轮已休 + brk` | 本轮被**截短**到剩余额度，剩下的时间回到专注 |
| 剩余额度 = 0 | 本轮休息**整段跳过**，继续保持专注 |

「跳过休息」的效果不只是不休息：`inBreak = false`，于是**锁机不解除、拦截继续**，
这正是"达到上限后保持学习锁机状态"。

### 边界

- 上限超过 60 无意义 → 夹到 60；负数按 0。
- 上限小于单次休息 → 每次休息都截到上限（如 45/15 上限 3：每次只休 3 分钟）。
- 被截断的休息之后不会再有休息（额度已归零），所以"休息结束后"一律算到整点。
- 上限**只影响相位判定**，不改变窗口（from/to）和排班本身。

### 验收

| 场景 | 期望 |
|---|---|
| 25/5，上限 0，09:25 | 休息中，还剩 5 分钟 |
| 25/5，上限 6，09:55 | 休息中，还剩 1 分钟 |
| 25/5，上限 6，09:57 | **专注中**（休息被跳过），锁机仍生效 |
| 45/15，上限 3，09:48 | 专注中，还剩 12 分钟到整点 |
| 50/10，上限 10 | 与不设上限完全一致 |
| 两端同一时刻对照 | 剩余时间、休息/专注判定逐字相同 |

自动化断言：Android `BreakCapTest`（7 条）、PC `clock::tests::phase_at_*` + `state_respects_break_cap`（5 条）。

## 2. 时段块：合并、平移、拉边界【Android 新增；PC 早已如此】

### 合并规则

数据仍按小时存（一小时可以有多个窗口，各带 `seg`），**展示与交互按"块"**：

- 同一 `seg` 且首尾相接或重叠 → **并成一块**（跨小时也不断开）；
- 不同 `seg` 只是紧邻 → 各是各的块（"相邻不等于同一段"，锁机"停止本段"要靠它）；
- 不同 `seg` 重叠 → 先出现的段占住重叠部分，后一段从它结束处开始（同一条时间轴上
  不能让两个段同时成立）。

### 手势

| 手势 | 结果 |
|---|---|
| 点一格 | 选中 / 取消这一格（会劈开所在块，可再点回来） |
| 长按**空白**后拖动 | 框选（新建一段，一次手势共用一个 `seg`） |
| 长按**块身**后拖动 | **整块平移**，长度不变 |
| 长按块的**第一格**后拖动 | 拉起点（改开始时间） |
| 长按块的**最后一格**后拖动 | 拉终点（改结束时间） |
| 直接上下滑 | 一格都不改，交给页面滚动 |

为什么按"格"而不是按像素分三区：一格只有 8/11dp，按像素分边缘区会小到点不住；
按格判还让 10 分钟与 15 分钟刻度共用同一句规则。
（PC 用鼠标，有线宽可用，所以是"距边界 7px 内 = 缩放，否则平移"，两者语义一致。）

### 边界与冲突（写死在一处：`Slots.moveBlock` / `Slots.resizeBlock`）

- 不越出当天 `00:00–24:00`；
- 撞到相邻块**停在它的边界上**，不覆盖、不吞并、不合并；
- 拉边界至少保留**一个刻度**的长度，且不能越过相邻块；
- 落点吸附到刻度（10/15 分钟，四舍五入）；
- 块级操作**跨列无效**（时间块不跨天）；
- 平移时番茄节奏跟着块走（`45/15` 搬过去还是 `45/15`），新建小时用默认值；
- 落在块上一点也动不了（顶到当天边界）→ 原样返回，界面表现就是"拖不动"。

### 验收

自动化断言：Android `SlotBlockTest`（13 条：合并/邻接不合并/重叠、平移保持长度、
撞邻居停边界、不越界、拉上下边界、不动别的小时、不重置节奏、老数据补 `seg`）。

## 3. 锁机提醒【Android】

三类提醒，各自可关：

| 提醒 | 触发 | 设置 | 频率 |
|---|---|---|---|
| 开始前提醒 | 距下一次锁机（或睡眠）≤ N 分钟 | `开始前提醒` 0–60 分钟，0 = 关 | **每一次只发一次**（按"开始时刻"去重） |
| 结束提醒 | 这一段真的走完时 | 不提醒 / 通知 / 弹窗 / 两者 | 每次结束一条 |
| 进入震动 | 进入锁机或睡眠的那一拍 | `进入时震动一下` | 每次进入 180ms |

### 关键判定

- 「真的走完」= 已经不在专注段，或自律/锁机被关掉。
  **暂停、停止本段、睡眠积分解锁都不算**（那是用户买来的自由，报"结束"是噪音）。
- 服务重启后的第一拍只建立基线：不震动、不补报"结束"。
- 结束弹窗要能盖住当前应用 → 需要悬浮窗或 Shizuku；**拿不到就只发通知**，
  并在正文与设置页都写明"已降级"，不假装弹过。
- 结束弹窗是提示页（`KIND_END`）：不拦返回键、10 秒自动退场、点一下就关。

### 验收

| 场景 | 期望 |
|---|---|
| 09:00 锁机、提前 5 分钟 | 08:55 收到一条"锁机即将开始" |
| 同一段持续 30 分钟 | 08:55 之后再没有第二条 |
| 番茄进入休息 | 收到"锁机结束"（休息是合法的） |
| 花积分暂停 | **不**收到"锁机结束" |
| 无悬浮窗 + 选"弹窗" | 收到通知，正文注明已降级 |

自动化断言：`NotifyPlanTest`（提醒窗口与文案）、`LockNoticeTest`（秒数计算）。

## 4. 震动与睡眠锁机【Android】

- 震动：进入锁机 / 睡眠的那一拍震 180ms（`VIBRATE` 权限，无需运行时授权）。
- 睡眠期间**必须锁机**：`sleep.lockScreen` 不再是可关开关，`normalize()` 一律置 true。
  老配置里关掉的，升级后按"要锁"处理。
- 睡眠锁机不依赖自律总开关与锁机开关（`SleepEngine.isSleeping` 独立判定），
  且不受锁机"暂停"影响；唯一的出口是积分解锁（有代价、有上限、到点自动收回）。
- 睡眠期间白名单应用仍可用（闹钟、笔记），其余一概盖住。

### 验收

| 场景 | 期望 |
|---|---|
| 自律关、锁机关、睡眠开 | 到点仍然整机锁住 |
| 锁机暂停中到达睡眠点 | 睡眠照样锁（暂停只管锁机那段） |
| 积分解锁一小段 | 到点自动收回，遮罩重新盖上 |
| 睡眠开始前 5 分钟 | 收到"睡眠时段即将开始" |

## 5. 锁机期应用限制【Android】

`锁机期间的限制范围` 三选一（`scope`）：

| scope | 有白名单规则 | 只有黑名单规则 | 都没有 |
|---|---|---|---|
| `all`（默认，整机锁） | 除白名单 + 紧急通道外全挡 | 同左 | 全挡 |
| `rules`（只按规则） | **只允许名单内** | **只禁黑名单** | 什么都不挡（设置页红字警告） |

- 睡眠恒为**整机锁**（与 `scope` 无关），但白名单应用仍放行。
- 紧急通道永远放行：状态栏、来电/拨号、电信、权限弹窗、输入法、自家应用。
- **禁止优先**：同一应用同时出现在两张名单里 → 按禁止处理（写进禁区是更强的表态）。
  判定顺序固定为：禁止名单 → 允许名单 → 整机锁 → 名单外（有允许名单时）→ 放行。
- 规则集合 = 启用中的规则 ∩ 这套时段绑定的分组（`GuardEngine.lockRules`）。
- 判定唯一出口：`LockEngine.decision`（遮罩、拦截、睡眠共用，避免两处打架）。

### 验收

| 场景 | 期望 |
|---|---|
| 整机锁 + 白名单含 A | A 可用，其它被挡 |
| 只按规则 + 只有黑名单含 B | B 被挡，其它可用 |
| 只按规则 + 白名单含 A | 只有 A 可用 |
| 睡眠 + 只按规则 + 只有黑名单 | 仍然整机锁；白名单可用 |
| 输入法 / 来电 / 状态栏 | 永远不被挡 |

自动化断言：`LockNoticeTest`（5 条判定场景）。

## 7. 待确认事项

1. **番茄休息段不拦截**：这是 PC 既有语义（休息是给你的自由时间），与"自律时段内严格生效"
   的字面要求有出入。若希望休息段也拦，改 `GuardEngine.activeRules` 里那一句
   `if (st.inBreak) return emptyList()` 即可，但要同步 PC，否则两端行为不一致。
2. **`scope = rules` 且一条规则都没有**：现在什么都不挡（设置页红字警告）。
   另一种做法是退回整机锁，但那样"只按规则"就没法表达"我只想挡几个应用"。
3. **块跨 23:00–24:00**：目前不跨天（一天一列）。要做跨天块需要把"块"提升到周维度，
   涉及锁机段标识与统计口径，属于结构改动，未做。

## 8. 强制模式的三重确认（0.4.1）

开强制模式 = 承诺"这一段不能停"。一个开关就能进这种状态，误触一次就是几小时，
所以必须连过三关：

| 步 | 问什么 | 选"是" | 选"否" / 按返回 |
|---|---|---|---|
| 1/3 | 是否要开强制模式 | 进入 2/3 | 取消，配置不变 |
| 2/3 | 生效期间的具体限制（不能暂停 / 不能跳过 / 只能用白名单 / 不能改设置 / 最长多久） | 进入 3/3 | 取消，配置不变 |
| 3/3 | 最后一次确认 | **写配置**（唯一写入口） | 取消，配置不变 |

- 「第几步」只存在于对话框状态里，**不进配置**，所以取消不可能残留中间态；
- 第 2 步会提示当前缺哪个能力（无前台 / 无遮罩 / 无 Shizuku），说明强制模式会打折；
- 判定本身是纯函数 `StrictFlow.advance / enables`，有断言兜住"第二步就开"这种错。

自动化断言：`StrictFlowTest`（5 条）。

## 9. 锁机失效的根因与修复（0.4.1）

**现象**：锁机时段内，白名单模式下仍能正常打开未加入白名单的应用。

**根因（两条，都在"兜底"上）**：

1. `enforceMask()` 在拿不到遮罩能力（没有悬浮窗 / Shizuku）时**直接 return**。
   遮罩没盖上、也没把用户送回桌面，等于锁机什么都不做——只发了一条"缺权限"的通知。
2. `showLock()` 的 800ms 节流是**丢弃**而不是延后：`goHome()` 之后 260ms 补的那一发
   很容易落进节流窗口被吞掉，那一拍就是"回到桌面但没盖住"。

**修复**：

| 位置 | 改动 |
|---|---|
| `enforceMask` | 能力不足 → 警告一次 + **回桌面**（不再静默 return） |
| `enforceMask` | 读不到前台 → **直接盖遮罩**（fail-closed，不再是"看不见就放行"） |
| `showLock` | 节流窗口内的请求**延后执行**，不再丢弃 |

**边界行为**（都有断言）：时段开始前不锁、进入时段锁、番茄休息不锁、下一小时未选中不锁；
强制模式忽略暂停/停止记录；切回温和必须等这一段结束。

## 10. 「展示锁机页面」两档（0.4.1）

| 设置 | 行为 | 白名单 |
|---|---|---|
| 开（默认） | 整机锁：回桌面 + 全屏遮罩，按现有锁机逻辑 | 名单内应用在锁机页可打开 |
| 关 | 不锁整机：桌面随便用，**点开黑名单应用**才弹 5 秒提示页并自动回桌面；非黑名单应用正常用 | **不参与判定**（没有整机锁，"只允许名单内"无意义） |

轻档提示页（`KIND_PAGE`）的边界：
- 5 秒**只在前台计时**：切后台暂停，回前台继续用剩余时间（否则用户根本没看到那 5 秒）；
- 按下返回 = 立即回桌面（不是"退回到底下的黑名单应用"）；
- 同一个应用 3 秒内只弹一次（否则会"弹→回来→再弹"，像坏了）；
- 拉不起界面（无悬浮窗 / Shizuku）→ 回桌面 + 通知，并说明已降级；
- 通知栏文案与点击目标跟着变：轻档下常驻通知写「仅拦黑名单应用」，点击回主界面。

自动化断言：`LockPageTest`（含两档判定、5 秒计时、边界与强制模式）。

## 11. 规则新增「白名单 + 黑名单同时生效」（`mode = both`）

- `packages` = 允许名单，`deny` = 禁止名单；
- 判定顺序（唯一出口 `LockEngine.decision` / `GuardEngine.blockedRule`）：
  1. 紧急通道、自家应用 → 放行
  2. **禁止名单命中 → 拦**（同一条规则里限制 entries 优先）
  3. 允许名单命中 → 放行
  4. 整机锁 / 睡眠 → 拦
  5. 有允许名单且不在名单内 → 拦
  6. 其余 → 放行（只有黑名单时，它只管名单内那几个）
- 允许名单为空时，`both` 退化成纯黑名单（否则一条规则能一键锁死全机）；
- 白名单规则里的 `deny` 也生效（"名单内但必须禁"的例外）；
- 跨端：桌面端的 `both` 名单在软件侧等价黑名单，导入时落在**禁止名单**；
  手机端带允许名单的 `both` 导出为 `whitelist`（只导出更严的一侧），禁止名单留在本机。

自动化断言：`LockPageTest`（both 优先级、退化、白名单内的 deny）。

## 12. 时段拖动：重排 + 视觉反馈（0.4.2）

### 为什么以前"拖不上去"

旧实现只有**绝对时间平移**：撞到相邻块就停在它的边界上。于是
03:00–04:00 与 04:00–05:00 这种贴身排列，后者一个像素都动不了——
它不是"排序错了"，是**根本没有排序这件事**。

### 现在的规则（`Slots.dragBlock`）

| 落点 | 行为 |
|---|---|
| 没越过任何块的起点 | 自由平移（仍在邻居边界处停住） |
| 起点越过了某块 | **重排**：这一块插到那个位置，受影响的那一段按原顺序、原长度重新首尾排开 |
| 往上拖且与某块起点**齐平** | 排到它**前面** |
| 往下拖且与某块起点**齐平** | 排到它**后面**（= 落在手指所在的位置） |
| 拖到最顶部 / 最底部 | 成为第一段 / 最后一段，从这一段最早的起点开始排 |

- 重排只影响"旧下标到新下标"这一段，**区间外的块一秒都不动**；
- 这一段的总跨度不变，所以不会把别的块挤出去、也不会重叠；
- 同一段里原有的空隙会被合上（顺序变了，原来的"缝"属于被移动的那一块）；
- 边界：起点夹在 `00:00 – (24:00 − 这一段长度)`，拖出当天不会消失。

### 视觉反馈（让用户确认"整段在动"）

| 元素 | 表现 |
|---|---|
| 被拖的块 | 四周外扩 1.5dp + 投影 + 2dp 对比色描边 + 圆角放大到 7dp（"浮起来"） |
| 块内文字 | 块高 ≥ 18dp 时在块顶写 `04:00–05:00`，直接给出"整段"的证据 |
| 落点占位 | 虚线框 + 20% 填充，重排时跟着"实际会落到哪"实时移动 |
| 顶部提示 | "正在移动 04:00–05:00 · 松手就放到这个位置" |

只有**被拖的那一块**高亮（以前按"当天所有块"高亮，看起来像整列都被选中）。

### 验收

| 场景 | 期望 |
|---|---|
| 03–04、04–05，把后者拖到 03:00 | 前者变 04–05，后者占 03–04 |
| 三块，把第一块拖到 05:00 | 落到 05:00，其余两块依次上移 |
| 把最后一块拖到最顶部 | 成为第一段 |

## 13. 更新通道：与桌面端对齐（0.4.3）

三端共用同一个 Release，也共用同一份 `King.Of.Focus-update.json`；
手机端只认清单里写给 `android` 的那一条，**绝不按扩展名扫资产**。

| 能力 | 桌面端 | 手机端（0.4.3） |
|---|---|---|
| 读清单选包 | ✓ | ✓（同一个 `Updater.select`） |
| 下载安装包 | ✓ | ✓ 应用内下载 → 校验大小 + sha256 + zip 头 → 系统安装器 |
| 浏览器兜底 | — | ✓「用浏览器打开」（应用内下载被网络掐断时） |
| GitHub 令牌 | ✓ | ✓（新增） |
| 配额显示 | ✓ | ✓（剩余 / 上限，检查时一并查） |

### 令牌（`UpdateCfg.token`）

- 匿名调用 GitHub API **每小时 60 次**，共享出口（公司 / 校园网 / CGNAT）很容易被用光，
  表现为 403；带令牌 **5000 次/小时**。
- 只发给 `api.github.com`；清单和安装包走的是公开下载地址，**不带令牌**。
- 只存本机：`Portable.toDoc` 不序列化 update 配置 → 不进备份、不进云同步（有断言）。
- 界面永不回显：输入框是暗文，只显示「已设置」；保存后立刻清空输入框。
- 401 与 403 给的是**两句不同的话**（令牌失效 vs 配额用尽），不是都甩一个 HTTP 码。

### 边界

| 场景 | 表现 |
|---|---|
| 没发 Release（只有 tag） | `E_NO_RELEASE`，明说"只有标签，无法自动更新"，不伪装成已是最新 |
| 清单里没有 android 条目 | `E_PLATFORM_MISSING`，不会去装别的平台的包 |
| 令牌错 / 过期 | `E_AUTH` + "重新填一个" |
| 配额用尽 | `E_RATE` + 提到 5000 次的建议 |
| 下载被掐断 | 错误说明 + 「用浏览器打开」 |
| 大小 / 哈希不符 | 删除文件并报错，绝不交给安装器 |
