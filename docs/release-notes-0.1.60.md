# v0.1.60 · 安卓统计补全三项指标；权限状态机；保活体检

安卓 **0.3.7**。桌面端功能不变。

## 一、三项指标：时长 / 次数 / 时段，两档都完整

以前统计页只有"用了多久"，而"一天翻四十次、每次三十秒"和"一口气看两小时"
在时长上看起来完全一样——对自律的意义却相反。现在三个指标**在每一档下都算**：

| 指标 | 含义 | 明细 |
|---|---|---|
| 时长 | 小时桶累计 | 每项应用时长 + 占比；日均；分时 |
| 次数 | 连续使用段个数 | 每项应用的次数 / 平均单次 / 最长一次 |
| 时段 | 峰值小时 + 最早最晚 | 24 小时分布（可点柱子看该小时明细） |

- 自律时段内 / 时段外 / 汇总 **各自都有全部三项**，不是"只有汇总才全"。
- 次数与单次长度来自 `spans`（分钟粒度）；分轨之前的老数据没有段，
  次数显示「—」而不是 0，并写明"只有小时桶"。
- 汇总时同名应用的两档段会先并到一条时间轴上再算次数——
  "自律时段内用了 20 分钟、时段外接着用了 10 分钟"是 **1 次**，不是 2 次。

## 二、时段对比 + 汇总结果

- **自律时段内 vs 时段外**：两条并列，各带时长 / 次数 / 占比条。
  单档视图下也照样显示——那正是判断"自律有没有起作用"的依据。
- **汇总卡**：两档合计时长、合计次数、活跃整点数，外加日均 / 峰值 / 平均一次。
- **明细**列**全部**条目（不再只列饼图那 8 项），每行两行文字：
  `Chrome 1 小时 21 分 61%` / `2 次 · 平均 40 分钟 · 最长 56 分钟 · 12:22–20:25`。

## 三、使用情况访问：四种状态、三种降级

`AppOpsManager` 只能回答"现在有没有"，可三种"没有"要三种处理：

| 状态 | 怎么判断 | 处理 |
|---|---|---|
| 从没给过 | `!granted && !grantedOnce` | 统计页顶部横幅解释 + 一键跳系统设置；拒绝后不再自动骚扰 |
| 给了又被回收 | `!granted && grantedOnce` | 明确写「被收回，统计已暂停」，服务停止采样并推一条通知 |
| 解释了但没给 | `!granted && asked` | 保留横幅，不再反复弹 |
| 已授予 | `granted` | 正常 |

**降级顺序**：使用情况访问 + 无障碍（最准）→ 只有使用情况访问（后台切换慢一拍）→
只有无障碍（前台能记、后台可能漏，横幅标"降级"）→ 都没有（**停止采样**，页面直说已暂停）。

实测：收回权限后 70 秒内统计增量为 **0 秒**；重新授予后立刻恢复 +58 秒。

## 四、保活：先体检，再按组合兜底

新增「设置 → 保活体检」，逐项列出权限与系统设置，每项可展开看
**用途 / 申请时机 / 缺失影响**，缺了就有「去开启」按钮：

使用情况访问 · 无障碍服务 · 在其他应用上层显示 · 通知 · 忽略电池优化 · 自启动（厂商，查不到状态，如实标"缺失"）

**措施组合**（新增两项）：
- 新增 **`JobScheduler` 15 分钟周期任务**：部分 ROM 拦 AlarmManager 但放行 Job，
  两条独立通道同时被拦的概率小得多。
- 新增 **回前台自愈**：每次 `onResume` 检查服务是否还活着，不活着立刻拉起——
  心跳最密也是 15 分钟，而用户点开应用的那一秒就该恢复。
- 另外补了「重启守护」「重新体检」两个按钮与 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 申请入口。

原有的：前台服务 + 常驻通知、`START_STICKY`、`onTaskRemoved` 补偿闹钟、
`AlarmManager` 心跳、开机/更新广播、电池优化白名单引导。

定位是"尽量活"，不是"绝对杀不死"——Android 上做不到后者，所以体检结果如实展示，
查不到的项（自启动）就写"无法检测"，不假装打勾。

## 验证（AVD kof35，20 天样例数据）

| 场景 | 结果 |
|---|---|
| 按日 10-31 · 三项指标 | 时长 2 小时 12 分（日均同）/ 次数 3 次（平均 44 分钟，最长 56 分钟）/ 时段峰值 12 点（12:22–20:25） |
| 时段对比 | 自律时段内 0 秒 vs 时段外 2 小时 12 分，占比 0% |
| 24 小时分布 | 24 根柱，汇总档深浅叠色；点 20 点 → `20:00–20:59 · 25 分钟` + Chrome |
| 明细 | Chrome `2 次 · 平均 40 分钟 · 最长 56 分钟 · 12:22–20:25`；Messages 1 次 |
| 汇总 | 时长 2 小时 12 分 / 次数 3 次 / 活跃整点 3 个 |
| 权限已授予、无障碍未开 | 横幅「统计精度可以更高」+ 一键开无障碍 |
| 收回权限 | 横幅「被收回，统计已暂停」；70 秒内统计增量 0 |
| 恢复权限 | 70 秒内 +58 秒，自动继续 |
| 保活体检 | 「守护在跑，但有 4 项权限缺失」+ 6 项逐条状态 + 去开启 |

单测：Android **161 条**全绿（新增 15 条：三项指标在两档/汇总下的一致性、
跨档段合并算一次、每小时分解、按小时取明细、老数据无段、权限四态与降级档位）；
桌面 Rust 241 / UI 1032 / i18n 656 全过（桌面未改）。

## 没做的

- **自启动状态的检测**：没有公开 API，只能引导到厂商设置页，如实标"缺失"。
- **强制保活白名单**（把本应用加入"后台不清理"的厂商白名单）同样只能引导。
