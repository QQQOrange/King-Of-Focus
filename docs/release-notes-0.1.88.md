# 0.1.88 / Android 0.5.6

这一版只补手机端：**总览页缺了桌面顶部那一行的三件事**。
桌面在 `ui/app.js` 里一直有「现在在不在段里 / 下一段几点开始 / 这一节被打断几次 / 今天写了几个目标」，
手机端只有倒计时、积分和今日时长——看起来差不多，但自由时间打开手机，
最想知道的恰恰是"下一次什么时候开始"。

## 1. 总览状态卡：下一段

不在自律时段、也没在锁机/睡眠时，状态卡多一行：

> 下一段 14:00 开始（20 分钟后）

算法是新文件 `core/BriefMath.kt` 的 `nextSegment`，逐小时扫、最多 7 天，
和桌面 `focus::next_segment` 是同一套笨办法。**不能另算一份**：
它和遮罩、锁机用的是同一份 `Slots.windowsOf`，口径差一格，用户就会看到
"显示下一段 10:00，可遮罩 09:45 就盖下来了"。

三个容易写错的点都有单测钉住：

- 正在段里的时候，返回的是**后面**那段（不能把当前段当"下一段"）；
- 一小时两段（09:00–09:20 与 09:40–10:00）时，09:10 的下一段是 09:40；
- 今天排完了要跳到下周同一格，而不是返回 null。

## 2. 总览状态卡：这一节已被打断几次

> 这一节已被打断 3 次

这个数字直接问 `LedgerStore.countBetween(段起点, 现在)`，和质押结算那句
"一次都没被打断才给 20% 奖励"是**同一个数**，不是另一份计数。
所以在总览上看到 0 次，结算时就一定是满额退回。

两处刷新节奏是有意的：段按**分钟**缓存（一小时里可能有两段，只按小时缓存会显示错段），
次数按 **10 秒**一档刷新（账本没有内存缓存，每秒读盘会影响滚动）。

## 3. 拦截页：这一节第 N 次被打断

被挡住的那一页原来只写"这个应用现在不能用 / 命中规则 X / 这一段要做的是 Y"，
现在多一行：

> 这一节第 3 次被打断

被拦下的三秒是决策窗口，"这是第 3 次"比任何一句"请专注"都管用。
它和上面那个数字、和时段结束时的汇总、和周复盘的账本是同一个来源。

## 4. 总览状态卡：今日目标

> 今日目标 3 个 · 做完 2 个

对应桌面的 `goalTotal / goalDone`。时长是过程，这才是结果——
排了 5 小时但一个目标都没写成，不该显示成"今天很棒"。
