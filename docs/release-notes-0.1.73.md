# v0.1.73 — 段目标与打断计数：让"我本来要做什么"出现在该出现的地方

> 主题：专注最容易漏掉的一环不是拦住什么，而是**开始前没写清要做什么**。
> 这一版给每一段加了一句目标，并把"这一段被打断了几次"变成看得见的数字。

## 一、段目标（HUD 上直接写）

- 专注时，HUD 里原来显示格言的那一行变成**这一段的目标**。
  没写的时候是一行虚线占位：「点这里写下这段要做什么」，点一下就能输入，回车保存。
- 为什么占用格言的位置：HUD 只有 272×122，加一行会把下面的东西挤没；
  而专注时"我原本要做的事"比一句格言有用得多。
- 一句目标只属于**这一段**：换段就是新的一句，改就是覆盖（同段不会堆成两条）。
- 不在自律时段里时按钮无效并明确提示，不会静默失败。

## 二、打断计数

- HUD 顶部出现「· 打断 2」，来自**本来就发生的拦截**（应用被送回桌面、网页被关掉），
  没有引入新的采样，也不额外打扰。
- 计数按段归零：换一段就从 0 重新数，不会背上一段的账。

## 三、时段结束的汇总

以前只在"记了分心事件"时才提醒，现在把三件事合起来说一句：

```
这一段结束了
目标：先写登录页 · 被打断 2 次 · 记下 3 条想法，去「分心事件」逐条处理
```

三者任一存在就会提醒；都没有就不打扰。这样一段结束时的问句从
"我坐了多久"变成"我要做的事做完了吗、被什么打断了"。

## 四、分心事件页

每个时段分组后面多了一个蓝色的段目标（如 `09:00–12:00 先写登录页`），
让"我原本要做什么 → 结果记下了什么"在同一行里对得上。

## 五、实现要点

- `src-tauri/src/focus.rs`：段目标（`intents.json`，一段一条）+ 打断计数（内存，
  按段归零）。判断"哪一段"复用 `distract::segment_bounds`，不另写一套。
- 打断计数挂在两个**真的拦了**的调用点上（`monitor` 应用拦截、`server` 网页拦截），
  而不是"碰巧看到"的地方——否则数字会虚高。
- 段结束用"一分钟前"的位置反查刚结束的那一段：翻面的那一刻，这一段已经不在范围里了。
- 目标与计数都留在本机，不进 `.kofbak`（这是"这一节课的笔记"，不是配置）。
