# 0.1.115 — 前端拆分：app.js（12860 行）→ 9 个按顺序加载的文件

这是"结构"那一批里最硬的一件。`ui/app.js` 从 2025 年一路长到 **12860 行 / 295 个函数**，
所有视图、动作、弹层、图表、事件绑定都挤在一个文件里。改任何一个视图都得在
一万两千行里翻，而且没法按模块测。

## 怎么拆的（以及为什么这么拆）

**不是**按功能重新编排，而是**连续切片、原样保留顺序**：

| 文件 | 行数 | 内容 |
|---|---|---|
| `app-core.js` | 441 | 工具 / 主题 / 状态拉取 |
| `app-views.js` | 2814 | 总览、规则与编辑器、图表拖选、时段、遮罩 |
| `app-stats.js` | 2128 | 统计、时间日历、报告、云同步、关于、帮助 |
| `app-settings.js` | 551 | 设置（含浏览器插件段） |
| `app-charts.js` | 689 | 饼图绘制 |
| `app-render.js` | 503 | 渲染调度、复制面板、启动巡检提示 |
| `app-actions.js` | 2552 | 全部动作（`Act`） |
| `app-ui.js` | 2406 | 弹层与事件绑定 |
| `app-boot.js` | 776 | 启动初始化（**必须最后加载**） |

为什么坚持连续切片：classic script 的顶层 `const` / `function` 共享同一个全局词法环境，
**按 `<script>` 顺序求值**。连续切片 = 求值顺序与原文件一模一样，语义完全等价；
按功能重新编排则要重新验证每一条全局依赖，风险高一个数量级。

每个文件头部都写明了这件事，并加了 `'use strict';`（原来只有第一行有，
拆开后每份都要有，否则非严格模式会掩盖拼写错误）。

## 连带改的三处工具（都会在拆分当天失效，必须一起改）

1. **`check_i18n.js`**：原来只读 `ui/app.js`。拆开后它会 `ENOENT` 崩掉；
   更糟的是如果只改路径不改逻辑，就会只扫其中一个文件——报告还是 100%，
   而英文界面里冒出中文。现在扫**全部** `app-*.js`，缺失项带 `文件:行`。
2. **`check_wiring.js`**：原来 `uiSrc['app.js']` 找分发器分支、`fs.readFileSync('app.js')`
   找重置分区清单，拆开后同样 ENOENT。现在把所有 `ui/*.js` 拼起来找。
3. **`index.html` / `_harness.html`**：`<script>` 按顺序列 9 个文件。

## 验证

拆完立刻跑全套，一条不少：

- `python tools/check_all.py` → **8 道全绿**（152 秒）
  - 界面 harness **1188 断言 0 失败**（这是拆分真正的安全网：它按视图逐个渲染并断言 DOM）
  - i18n **842/842**（证明多文件扫描没漏）
  - 接线一致（证明分发器分支都还在）
- 截图核对总览页：状态卡、积分卡、节奏卡、语录条全部正常
- 版本：桌面 0.1.115 · Android 0.7.0（未改）· 插件 1.2.3（未改）

## 下次改前端时

- 改视图 → `app-views.js` / `app-stats.js` / `app-settings.js`
- 加动作 → `app-actions.js`（`Act` 对象 + 分发器在 `app-ui.js`）
- **不要**调整 `<script>` 的先后顺序：`app-boot.js` 里有启动时的 `pull()` 与定时器，
  提前就会在 `S.data` 还没拿到时执行。
