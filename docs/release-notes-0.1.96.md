# 0.1.96 / Android 0.5.9

上一版结尾列了四条"还没做的"，这一版把它们做完了。

## 1. 手机端恢复不再绕过纪律

桌面端在恢复备份前会调 `config_replace_blocked`：自律时段内、或固化锁定中，**整份替换一律拒绝**。
手机端两条恢复路径（云端 / 本地文件）都是直接 `Store.update`——自律时段里导入一份
"规则全关"的旧备份，就等于一键解除自律。

现在手机端加同一道闸：`Portable.overwriteBlocked()` 用 `ScheduleEngine.frozen`
（时段内 + 未解锁 + 本段没停）判定，命中就拒绝覆盖并提示"改用合并"。
合并仍然允许——它只做加法，不会削弱纪律。

## 2. 插件两层判定口径统一

- **跨规则例外**：DNR 把例外编译成 `priority: 25 allow`，本来就压过所有规则的拦截（20），
  请求层是"任何一条规则的例外都放行"。而 JS 那一层是"逐规则跳过"，
  于是同一个网址会"新开被放行、已开的标签页却照样被关"。现在两层统一成**全局放行**。
- **请求超时**：4 处 `fetch` 都没有超时。本机某个服务占了 27315 却不回数据时，
  `/api/ping` 永久挂起，后面每次 refresh 都排在它之后——用户看到的是"插件在跑、规则再也不更新"。
  现在探测 400ms、状态拉取 3s、心跳/上报 2s，超时就换端口/下一轮。

## 3. 手机往返不再丢东西

- **指纹算法**：手机端的 `sig` 只拼允许名单，两条只在"禁止名单"上不同的规则指纹相同，
  合并时第二条会被当成"已存在"跳过。现在把 `deny` 拼进去，与桌面同义。
- **规则颜色**：`needsCarry` 不看 `color`，只改了颜色的规则往返手机后被重置成默认橙。
  现在非默认色会进 `carry` 原样带回。

## 4. 英文模式的动态文案

带变量的提示绕不过精确词典（`已解锁 5 分钟，消耗 21 分` 这种）。给最常用的十几条
加了正则规则：解锁、检测完成、导出/删除失败、备份生成、短语间隔、时段清空/整天选中……
