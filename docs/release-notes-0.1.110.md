# 0.1.110 / 插件 1.2.3 — 一轮真 bug 修复

上一条发的四项功能里，复查出 **5 个真问题**，全修了。

## 1. get_state 增量：写了，但其实从没生效

指纹是 `u64` 哈希，经 JSON 传给前端后变成 JavaScript 的 `Number`——只有 53 位精度。
大数被四舍五入，前端回传的 `since` 和 Rust 算出来的永远对不上。

后果很隐蔽：**不报错、不崩溃，只是每次都照样传整份配置**，优化等于没写。

修法：哈希砍到 53 位（`& 0x1F_FFFF_FFFF_FFFF`），两端整数表示完全一致。

## 2. 专注条收起来就再也打不开

收起态把唯一能点的「–」按钮也隐藏了，圆点本身不可点——用户点一下收起，
之后只能刷新页面才能再展开。

修法：整条都可以点（收起态是圆点，展开态是整条），按钮仍然可用。

## 3. 全屏最小化：每秒执行一次

"拦截前先最小化"写在每次轮询都会走到的位置。目标关不掉时（权限不足等），
它会**每秒**调一次 `ShowWindow` 并写一条日志，几秒就把 `mlog` 刷满，
真正要排查的内容反而被冲掉。

修法：只在第一次动手时最小化（`pending` 里没有这个 pid 时）。

## 4. 安全模式会误判"正常开关"为崩溃

判定是"两次启动间隔 < 120 秒算异常，连续 3 次进安全模式"，而"这次启动活过 90 秒"
才清零。于是**开→关→开→关，每次不到 90 秒**，三次就进安全模式：不拦截、不遮罩，
用户什么都没做错。

修法：正常退出（`RunEvent::Exit`）也调 `boot::mark_ok()`。

## 5. 节奏/热力图的两处性能与新鲜度问题

- **节奏**每次重算要读最多 104 个日文件（90 天连续 + 14 天周对比），
  而它在 `get_state` 这条每秒都走的路上 → 每分钟一次肉眼可见的卡顿。
  修法：历史日期的秒数缓存住（历史不会再变），只让"今天"每次重读。
- **热力图**只按日期缓存，今天这一格早上打开、下午再看还是早上的颜色。
  修法：加 5 分钟过期。
