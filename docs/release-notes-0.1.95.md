# 0.1.95

这一版是**全盘审视**：四个方向（Rust 稳定性 / 业务边界 / 前端死角 / 多端一致性）各审一遍，
修掉确认的问题。最要紧的不是某一条 bug，而是**自检本身有两个洞**——先补上它们，
否则后面所有"全绿"都不可信。

## 一、自检工具的洞（最要紧）

- **`run_itest.js` 把两元素断言当成"记录行"跳过**：`_harness.html` 里大量
  `out.push(['清空全部', pd().every(...)])` 是"期望 true"的真断言，从来没参与比较，
  等于永久静默通过。现在两元素按"期望 true"比较，断言数从 1103 涨到 **1188**，
  立刻暴露出 3 条真实问题（见下）。
- **`release.py` 引用未定义的 `NOTES`**：清单里 notes 为空时抛 `NameError`，
  在"已经开始发布"的位置崩，看起来像上传失败。
- **`check_i18n.js` 扫不到 `textContent = '中文'`**：这类文案漏翻也报 100%。

## 二、数据安全

- **`save_config` 用前端快照整份覆盖**：前端发的是上次 `pull` 的配置（最多 1.5 秒前），
  这期间后台加的积分、买的解锁、写回的同步状态会被"退回"，而且磁盘一起退回。
  现在服务器自己维护的字段（积分、对端摘要、同步时间）一律以内存现值合并。
- **`update_check` 把 12 秒前的快照写回**：检查更新时先发网络请求再写回旧配置，
  这 12 秒里的所有改动静默回滚。现在只更新"上次检查时间"这一个字段。
- **`monitor` 持着 `rt` 锁写文件**：每 20 秒的会话存档落在锁内，磁盘一慢就卡住
  拦截判定和界面轮询。改成锁内取值、锁外落盘。
- **备份的残缺文档会清空规则**：只带 `settings` 的文档能通过解析，覆盖模式会把
  所有规则和时段清成空。现在覆盖模式必须同时有 `rules` 与 `clock`；恢复前先把
  当前 `config.json` 存一份 `config.pre-restore-<时间>.json`。
- **手机端恢复没有任何校验**：`{"kof":"king-of-focus"}` 这种残缺文件在手机上算"合法备份"，
  覆盖后规则清零。补齐与桌面同一套四道判据（format / schema / 分区 / 无内容）。
- **手机备份会把桌面的设置"反向覆盖"**：手机端写死 `applyRules: true`、把
  `totalEarned` 写成当前余额。桌面恢复时现在保留本机的 `applyRules`，
  `totalEarned` 取较大值。

## 三、判定与状态

- **两段贴合的时段被并成一段**：09:00–10:00 与 10:00–11:00 是两次画出来的独立时段，
  后端只看边界，于是第二段沿用第一段的段目标、打断计数累加、押注提前结算。
  现在按 `seg` 判连续性；连续选中 ≥24 小时时起点也不再随时钟滑动。
- **积分解锁期间统计仍记"自律开启"**：与"解锁时间不发积分"口径矛盾。
  现在解锁窗口内不算自律开启（记到未开启）。
- **锁屏盾牌每 1.5 秒重建 innerHTML**：英文界面会退回中文，唯一出口按钮每 1.5 秒
  被替换一次、键盘焦点掉回 body。改成只更新变化的文本。
- **恭喜/更新弹窗直接覆盖编辑中的规则**：现在有编辑弹窗时排队，不覆盖。

## 四、交互死角

- **HUD 目标编辑框不回填**：点开是空白，直接回车就把已有目标清掉（静默数据丢失）。
  现在回填当前目标，空回车 = 取消。
- **启动时一次 `get_state` 失败 → 窗口永久死掉**：不轮询、不重试、主题语言都没初始化。
  现在轮询照起，界面给"重试一次"。
- **首启动向导被插件提示盖掉**：新人第一次看到的是"插件没装"而不是三步引导。
  两者排队，向导优先。
- **Esc 关掉"选择恢复方式/输入旧密码"弹窗 → `await` 永不返回**：恢复既没成功也没失败，
  什么提示都没有。现在任何关闭路径都会兑现。
- **输入框右键没有粘贴菜单**：粘贴 GitHub 令牌、粘贴浏览器路径都做不了。输入控件保留原生菜单。
- **英文界面成对漏翻**：`休息中 / 自由时间 / 专注遮罩已关闭 / 未注册 / 创建 …` 十余条补齐。
- **「启用分心事件」开关没有 handler**：点了不保存，重绘后又亮回去。
- **时段菜单缺"这一小时的刻度表"**：右键一段时看不到该小时的四个 15 分钟刻度。
  现在补上（点一下切掉/补回），`run_itest` 的 3 条真实失败也由此修掉。

## 五、稳定性

- **"1.5 秒内按过 Alt"被当成 Alt+F4**：Alt+Tab 切回来马上点 X 会真的退出程序
  （用户以为只是收进托盘）。现在只有 Alt+F4 组合才记时间戳。
- **退出时先释放单实例锁**：退出清理还要几百毫秒，这期间被拉起会出现两个实例。
  放锁挪到最后一步。
- **退出时遮罩线程来不及收尾**：600ms 预算小于遮罩单帧最长等待（1000ms），
  超时后"还原置顶/摘顶"被跳过——用户的播放器会永久钉在最上层。
  预算提到 2 秒，并加一条**不依赖线程**的兜底还原（影子表）。
- **睡眠关机与积分解锁竞态**：可能"积分扣了、机器照关"。发关机前复核一次配置。
- **关机命令失败被吞**：以前只静默失败且不再重试，现在提示"关机没有执行，请手动关机"。
- **`prune` 遇到超大 `retentionDays` 会 panic**：跑在统计线程里，一 panic 自动报告
  整条线程死掉。sanitize 夹到 30–3650，`prune` 用 `checked_sub_days`。
- **锁中毒后 `sleep` 线程每秒 panic**：`arm_slot().lock().unwrap()` 改成
  `unwrap_or_else(|e| e.into_inner())`，与其它模块口径一致。
- **`percent_decode` 按字节切 `&str`**：URL 带中文就 panic（调试接口）。

## 六、文档

README 修正了一批与实现不符的描述：DNR 优先级数字、单一标签页的处理、插件轮询频率、

`check_portable.js`）、补上从没出现过的 `check_wiring.js`。
