# v0.1.56 · 修「自律时段」误触：滚动不再改选中，拖选要先长按

安卓 **0.3.3**。桌面端功能不变，版本号跟着发布走。

## 问题

上一版把整块网格当成一个画布，**按下去就开始涂**。网格比页面高，而要滚动页面
就得从格子上起手，于是"想往下翻"变成"顺手改了一大片时段"，而且一改就是连续几个小时。
这不是手感问题，是一改就可能改错计划的事故。

## 现在的交互

| 动作 | 结果 |
|---|---|
| 点一下 | 切换这一格，并把它记作**拖选起点**（起点画一圈描边） |
| 长按（约 0.5 秒） | 进入拖选状态，伴随一次触感反馈 |
| 长按后上下拖 | 从起点到当前格整段框选，反向拖回去即撤销 |
| **直接上下滑** | **一格都不改**，交给页面滚动 |

关键实现（`ui/ScheduleScreen.kt`）：指针按下后**先不消费**任何事件，
用 `withTimeoutOrNull(longPressTimeout)` 等长按；期间指针移动超过 `touchSlop`
就直接 `return`，把手势完整让给滚动容器——不消费、不落盘、不动数据。
只有超时成立才切进拖选，之后才 `consume()` 并整段涂。

另外两点：

- **长按本身不改数据**：只设起点、切状态。以前会顺手涂一下，
  结果"手滑长按"就悄悄删掉一格计划。
- 涂成"选中"还是"取消"由起点当前状态决定：先点一下把它取消（起点变取消态），
  再长按同一格拖动，就是**整段擦除**。这正好是"先选中起始时段、再长按拖选"的用法。

鼠标与触控走同一条判定：`pointerInput` 只认指针事件，不看输入源；
双击/滚轮都不受影响（滚轮不是按下事件，根本不进这条路径）。

## 验证（AVD kof35，触控 + `input mouse` 两种注入）

| 场景 | 结果 |
|---|---|
| 格子上直接上下滑（空计划） | 页面滚动（06:00 → 10:00），数据仍为 0 分钟 |
| 已有 11:00–12:30 时再滑 | 数据一分不变 |
| 点一格 | 只选中 15 分钟（11:00–11:15） |
| 点起点 → 长按同格向下拖 | 07:45–09:30 连续段 |
| 点起点 → 长按**向上**拖 | 10:30–12:15 连续段（方向无关） |
| 点一下起点（取消态）→ 长按向下拖 | 整段被擦除，只剩没拖到的部分 |
| 长按后不动就抬手 | 数据不变（长按不写数据） |
| 锁定列（周一）长按拖 | 数据不变 |
| 鼠标拖动（无长按） | 数据不变 |
| 鼠标单击 / 鼠标长按拖 | 选中一格 / 连续段，与触控一致 |

单测：Android **106 条**全绿（新增 `Slots.dragRange` 的方向无关断言）。

## 代价

长按进入拖选比"按住就涂"慢约 0.5 秒。这是刻意的取舍：
误改一份几小时的计划，比多按半秒难恢复得多。
