# 0.1.109 / 插件 1.2.2 — 上一条里"没做的四件"全做了

## 一、新标签页（插件）

`chrome_url_overrides` 接管新标签页：大时钟、日期、当前自律状态与剩余时间、
今日自律进度条、今天的目标与完成标记、一句语录。

- 数据全部来自 `chrome.storage.local`（background 每 12 秒写一次），
  **新标签页不发任何网络请求**——它是打开频率最高的页面，不能因为它变慢；
- 没有目标时给一句引导（"打开 King Of Focus 开始一段专注"），不留空白；
- 中文/英文跟随主程序设置。

## 二、全屏应用：先最小化，再关闭

独占全屏（尤其 DirectX 游戏）时遮罩压不上去，用户看到的是"游戏画面卡住、
通知在别的窗口里"，像是程序没反应。

现在拦截一个应用之前先 `SW_MINIMIZE` 一下：桌面立刻回来，通知和主窗口都看得见，
关闭流程照常继续。**只改变"看得见/看不见"，不改变任何拦截判定**。

## 三、令牌统一（tokens.css）

主界面的 172 行设计令牌（颜色、圆角、四级动效时长、浅色覆盖）从 `app.css`
抽到独立的 `ui/tokens.css`：

- `index.html` / `_harness.html` / `hud.html` / `sleep.html` / `toast.html` 都在
  自己的样式**之前**引入它；
- HUD 的强调色改成 `--hud-gold: var(--gold)`，不再各窗口各写一份蓝；
- 浅色主题的覆盖块跟着令牌一起搬走。已用无头浏览器核对：
  `data-theme=light` 时 `body` 背景为 `rgb(245,246,250)`、样式表 2 份（tokens + app）。

## 四、get_state 增量

界面每 1.5 秒拉一次状态，而配置几分钟才变一次。原来每次都把整份配置塞进 IPC，
等于每秒序列化 + 传输 + 解析十几 KB 的无用数据。

现在：

- 后端对配置做**内容指纹**（序列化一次再哈希，几十微秒），和前端带来的 `since` 比对；
- 一样就把 `config` 置 `null`，前端保留上一份（`pull()` 里合并）；
- 用内容哈希而不是"写配置时 +1"的版本号：全项目三十多处直接写 `cfg`，
  逐处加计数一定会漏，漏了就是界面停在旧配置上，极难查；
- 指纹在跨天重置之后计算，保证和真正发出去的那份配置一致。

## 六、注意

新标签页接管是**强体验变化**：装上新版后，开新标签页看到的是 KOF 的页面。

这一点也写进了设置页的说明里。
