# 0.1.116 — 总览不再每秒整页重绘（局部刷新）

## 问题

`pull()` 每 1.5 秒拉一次状态，总览页**每次都把整个视图的 innerHTML 重建一遍**：

- 每分钟约 40 次 DOM 重建；
- 每次都连带重算图表、日历、热力图（`render()` 的后处理）；
- 你在总览上滚动位置、文本选中都会被打断；
- 笔记本上能听到风扇跟着一下一下地响。

而实际上，绝大多数时候屏幕上一个字都没变——积分没动、段没换、拦截数没涨。

## 做法：先比"可见状态指纹"，没变就不重绘

新增 `overviewSig()`（`app-views.js`），把 `viewOverview()` 真正读过、真正显示在屏幕上的
字段拼成一个字符串：状态、剩余秒数、拦截数、生效规则名、积分与价格、遮罩状态、
今日目标与进度、上一段复盘、语录文本……

- `pull()` 里比一次：一样就**整页不重绘**，一样都不用做；
- 不一样才走原来的 `render()`；
- `render()` 结束时把这次的指纹记到 `S.ovSig`。

秒级噪音要量化，否则指纹每拍都变、等于没省：心跳与倒计时按 **10 秒取整**。

## 实测（headless 里数出来的，不是估的）

```
连续 6 次 pull（状态不变）→ render 调用 0 次
把指纹改成过期值 → 1 次
再 pull 一次 → 0 次
```

也就是从「每 1.5 秒重建一次」变成「只在真的变了时重建」。

## 这条设计的代价与边界

- 指纹**漏一个字段**的代价是那一项最多旧 10 秒（不是错，只是不新）——所以宁多勿少，
  我把 `viewOverview()` 读过的字段都列进去了；
- 只作用于**总览**：其它页面本来就是事件驱动重绘，没有每秒重绘的问题；
- 编辑规则时（`S.editing`）依旧完全不重绘，行为和以前一致。

## 验证

- `python tools/check_all.py` → **8 道全绿**（155 秒）
- 界面 harness **1188 断言 0 失败**（含总览页的全部断言）
- 版本：桌面 0.1.116 · Android 0.7.0（未改）· 插件 1.2.3（未改）

## 你可以感受的

打开总览，盯着一分钟：数字照常更新，但**页面不再整体闪一下**，
滚动位置也不会被重置。
