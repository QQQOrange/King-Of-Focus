# King Of Focus 功能审查报告 · 2026-10-31

审查对象：Windows 桌面版（`src-tauri` 2.1 万行 Rust + `ui` 2 万行原生 JS），版本 0.1.46。

## 二、本次已修复（5 处高危）

| # | 问题 | 位置 | 修复 |
|---|---|---|---|
| 1 | **配置非原子写**：`fs::write` 先截断再写，写入中崩溃即 0 字节；守护进程每 2 秒读一次，读到半截 JSON 会退回默认配置（自律时段=关）→ 固化判定失效并自行退出 | `cfg.rs:84` | 改为 tmp + rename；新增损坏文件留档（`config.broken-<ts>.json`） |
| 2 | **同步上传凭据**：`payload()` 序列化整份 Config，WebDAV 口令、备份口令、更新令牌明文 PUT 到网盘 | `sync.rs:43` | 上传前清空 `sync.url/username/password`、`backup.password`、`update.token` |
| 3 | **固化期间可退出**：`force_quit` 只查 `session_quit_hint`，不查固化锁定；热键 / Alt+F4 / 设置页按钮都能在固化中关掉程序 | `forcequit.rs:398` | 增加 `guard::lock_info().locked` 拦截并提示 |
| 4 | **积分解锁不解拦截**：界面承诺"解锁期间所有拦截暂停"，实际只有 `guard::lock_info` 读 `unlock_until`，软件/网页照拦、遮罩照盖 | `discipline.rs:114`、`monitor.rs:304` | 在 `active_rules`（唯一判定入口）与遮罩 `schedule_on` 上加解锁判定 |
| 5 | **固化开关无入口**：`hardToggle` 与 `data-act="hard-toggle"` 分支都在，但没有任何元素触发，新建规则一律 `hard: true` | `ui/app.js:1124` | 在「固化」页补上真正的开关 |

验证：Rust **215** 条断言通过（新增 2 条：上传体不含凭据、解锁期间规则为空）；界面 **1010** 条断言全绿。

## 三、未修问题（按建议优先级）

### 高

| 问题 | 位置 | 建议 |
|---|---|---|
| 守护进程可能被"半截配置"打掉（已随原子写缓解，但仍需防御） | `guard.rs:467` | `load()` 失败时保持上一轮判定，不要当默认配置 |
| 同步下载会覆盖本机 `backup.password`/`update.token`/`run_as_admin`/`autostart` | `sync.rs:100` | 与 `backup.rs:282` 对齐，保留机器专属字段；`save` 失败要上报 |
| 多处 `cfg::save` 不更新 `updated_at` → 自动同步 last-write-wins 把本地改动冲掉 | `cmds.rs:756/1421/1433/1308`、`shared.rs:151` | 抽 `save_cfg(&Shared, Config)` 统一入口，内部刷新 `updated_at` |
| 日统计解析失败后被空对象覆盖写回，一天数据永久丢失 | `stats.rs:178`、`588` | 解析失败改名 `.json.bad` 并提示一次 |
| `stop_guard` 终止失败仍删 pid 文件 → 孤儿守护反复复活主进程 | `guard.rs:529` | 终止失败保留 pid 并返回错误 |

### 中

- 自动备份错误被 `let _ =` 吞掉；备份目录不跟随 `data_dir` 回落（安装到 Program Files 时会写失败）。
- 自动日报只补"昨天"一天，停机多天中间的报告永远缺失；生成失败也标记为已生成。
- 更新只校验 `Content-Length + >100KB + MZ`，chunked 响应下等于不校验；安装脚本不检查 `ERRORLEVEL`，失败无回滚。
- 开机自启 `reg add`/`schtasks` 返回值全部丢弃，失败也报成功。
- `guard_running` 只置位不复位，守护被杀后不再拉起。
- 遮罩抬升/摘顶的句柄只在内存，强杀后用户窗口永久 topmost（无自愈）。
- 白名单模式下"网站例外"完全不生效（Rust 与扩展两处都不看 exceptions）。
- 固化判定忽略「方案绑定」，未绑定的规则也会锁人。
- 恢复备份前不生成快照，误恢复无法撤销。
- 配置解析失败只 `eprintln`（GUI 无宿主），用户不知道规则已重置。

### 低

- 第二个实例启动不提示、不唤起已运行窗口（双击 exe 看起来"没反应"）。
- `notify.focusWindow` 字段读了但永远 false（无入口、命令参数也没有）。
- 自定义浏览器的"扩展页地址"永远为空。
- 6 条后端命令无前端调用（`test_mode_status`/`quit_app`/`hide_window`/`show_main`/`stats_flush`/`browser_check_path`）。
- 规则级 `lock`（时长/密码/文字）只有前端残留，后端零校验。
- 英文界面仍有约 180 条可见文案无词条、14 处词条键冲突。

---

## 四、结论

- 核心链路（时段 → 番茄 → 拦截 → 固化 → 积分）**已打通**，但有 5 处高危断链，本次已修。
- 剩余问题集中在**异常兜底**（写盘、解析、网络、进程身份）与**文案承诺**（时间表、固化、例外），
  不影响主流程，但会让"看起来生效、实际没生效"的情况反复出现。
- 建议下一轮优先级：统计/同步的数据安全（高）→ 守护自愈与遮罩残留（中）→ 文案与死代码清理（低）。

## 五、第二轮修复（v0.1.48）

第三节里"会丢数据 / 承诺落空"这一档的 13 项已全部修掉：

**数据安全**
1. 统计日文件解析失败时留档 `.json.bad-<时间戳>`，不再用空对象覆盖原文件；
2. 跨天轮转先 `load_day` 读回已有的"今天"，时间回拨不再清空当天数据；
3. 自动日报从上次生成日的下一天逐日补，写成功才推进游标；
4. 同步下载保留 `backup.password`/`update.token`/`run_as_admin`/`autostart`，写盘失败上报；
5. `cfg::save` 统一刷新 `updated_at`，本地改动不再被自动同步冲掉；
6. 配置损坏留档带时间戳，并在启动后提示一次（GUI 下 `eprintln` 无人可见）。

**自愈**
7. `stop_guard` 终止失败时保留 pid 文件，避免孤儿守护反复复活主进程；
8. 守护存活每 5 拍复核，被任务管理器杀掉后能自动补回；
9. 备份目录跟随数据目录（不再绑死 exe 所在盘），自动备份失败会提示；
10. 开机自启写入失败返回 `Err`，界面不再假报成功。

**承诺落空**
11. 白名单模式下网站例外生效（判定层 + DNR 声明式规则层都补齐，新增 3 条匹配器断言）；
12. 固化判定按「方案绑定」过滤，与 `active_rules` 同口径；
13. `apply_autostart` 改为 `Result`，失败能一路传到界面。

验证：Rust 215、插件匹配器 47、界面 1010，全部通过。

**仍然保留的已知问题**：更新包完整性校验强度、安装失败无回滚、遮罩 topmost 残留不自愈、
`Rule.lock` 前端残留、6 条无调用命令、英文界面约 180 条缺失词条、规则级番茄页不生效。

## 六、第三轮修复（v0.1.49）

**更新链路**
1. 下载完整性改用 Release 资产清单的 `size` 校验（chunked 响应下原来等于不校验）；
2. 安装脚本检查 `ERRORLEVEL`，失败写 marker，下次启动明确提示，不再假报"更新完成"。

**界面不再误导**
3. 规则编辑器移除「休息」页 —— 规则已无自己的时间表，这一页配了不生效；
4. 同步去掉规则卡片上的「番茄 x/y」徽标；
5. 删除规则「锁定」（时长/密码/文字）的前端残留（无入口、后端零校验，改配置即绕过）。

**澄清**
6. 6 条无界面入口的后端命令保留，并在 `main.rs` 注册处注明用途与替代入口（预留，非漏接）。

验证：Rust 215、匹配器 47、界面 1010。
