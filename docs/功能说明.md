# King of Focus · 功能说明书

> 版本 0.0.1 · 开发者 QQQOrange · https://github.com/QQQOrange/King-Of-Focus

---

## 一、功能概述

King of Focus 是一个 Windows 上的自律计时与拦截工具。核心模型只有三层：

| 层 | 含义 |
| --- | --- |
| **规则（Rule）** | 一份名单（软件 / 网站分开）+ 一张周时间表 + 休息设置 + 固化开关 |
| **时间段（Slot）** | 时间表里的一天中的一段，例如「周一 08:00–11:00」 |
| **自律周期（Cycle）** | 时间段内按「专注 N 分钟 → 休息 M 分钟」循环出的一轮专注，即一次"自律周期" |

规则只在它自己的时间段内生效；进入时间段后按番茄参数切分成一个个自律周期；
自律周期内黑名单里的软件和网页会被拦住，休息段放开；周期结束弹一次恭喜。

## 二、可配置项

### 1. 规则级

| 项 | 取值范围 | 说明 |
| --- | --- | --- |
| 名称 | 任意文本 | 显示用 |
| 模式 | 黑名单 / 强制模式（白名单） | 黑名单=名单内不许开；白名单=只许开名单内 |
| 软件名单 | exe 路径 / 文件夹 / 进程名（支持 `*`）/ 窗口标题 | 与网站名单分开维护 |
| 网站名单 | 域名 / 路径前缀 / `*` 通配 | 由浏览器插件执行 |
| 网站例外 | 同上 | 优先级高于网站黑名单 |
| 时间表 | 周一~周日 × 任意多段，30 分钟粒度 | 全空 = 全天生效 |
| 休息 | 不休息 / 番茄（专注 N 分钟 + 休息 M 分钟，N 1~240、M 1~120） | 从时间段起点开始循环 |
| 固化 | 开 / 关，**新建规则默认开** | 见第五节 |
| 颜色 | 预设色 | 列表标识 |

## 三、时间规则

### 1. 每日设置的存储与生效

- **存储位置**：`king of focus data/config.json` → `lists[].schedule`，是一个长度 7 的数组（索引 0 = 周一），
  每天是一组 `{start, end}`，单位是**从 00:00 起算的分钟数**（如 480 = 08:00，660 = 11:00）。
- **生效方式**：规则绑定的是"周循环"，不区分具体日期。这周设成周一 08:00–11:00，
  下周、下下周的周一都是 08:00–11:00，**不需要"设置完某个任务后每天重复"这一步**——
  想让它每天重复，就把同一段复制到 7 天（编辑器里有「周一 → 全部」一键按钮）。
- **改完立刻生效**：保存时写盘 + 替换内存配置，拦截引擎下一次扫描（≤1 秒）就按新时间表判定，不用重启。
- **判定口径**：`当前时间 ∈ 某天某段` → 该规则生效；至少一条规则生效 → 自律模式 = 已开启。

### 2. 多个学习时段叠加时的循环计算

番茄循环**按"当前所处的那一段"独立计算**，不会跨段累加：

```
段 A 08:00–09:30，专注 40 / 休息 20：
  08:00–08:40 专注  08:40–09:00 休息  09:00–09:30 专注（不足一轮就按段尾截断）

段 B 10:00–12:00，同一套参数：
  10:00 重新从「专注」开始 —— 锚点是段 B 自己的起点，不接着段 A 的进度
```

- 锚点 = **该时间段的起点**（不吃"程序启动时间"，也不吃"昨天剩的进度"）
- 同一天里两个段之间有间隔：间隔期规则不生效，什么都不拦
- 同一条规则的多段之间不重叠；不同规则可以重叠，各自独立判定，**任意一条要求拦截就拦截**
- 跨夜段（如 23:00–01:00，`end < start`）按 `end += 1440` 处理，循环连续不中断

## 四、通知逻辑

### 1. 触发点

| 类型 | 提前量 | 实际触发时间点 |
| --- | --- | --- |
| 学习（自律周期）结束提醒 | `X` 分钟（默认 5，可 0~120） | 当前专注阶段**还剩 ≤ X 分钟**的那一秒（引擎 1 秒一扫，误差 ≤ 1 秒） |
| 休息结束提醒 | `Y` 分钟（默认 2，可 0~120） | 当前休息阶段还剩 ≤ Y 分钟的那一秒 |

### 2. 频率与去重

- **每个阶段只提醒一次**（不是每分钟都提醒）
- 阶段切换时自动重置：剩余时间从"小"跳回"大"（跳增 > 5 秒）即判定进入新阶段，可以再次提醒
- 提醒内容形如「本轮专注还剩 5 分钟，坚持一下」/「休息还剩 2 分钟，准备回到专注」
- 表现：主界面右下角弹提示；同时 HUD 上的倒计时变金色闪烁

### 3. 休息提醒可以单独关闭

`休息也提醒` 关掉后：学习结束照常提醒，休息结束**不再提醒**。`启用提醒` 是总开关，关掉后两种都不发。

### 4. 取值合理性

- 学习提醒 > 学习时长 → 不会触发（因为剩余时间永远大于阈值），等于关闭
- 学习提醒 = 0 → 关闭该类型
- 休息提醒 > 休息时长 → 进入休息的第一秒就提醒（等价于"休息开始即提示"）

## 五、边界情况

| 场景 | 实际行为 |
| --- | --- |
| **时段跨天** | `end < start` 视为跨夜（如 23:00–01:00 表示次日 01:00 结束），循环锚点仍是段起点，跨天不断档 |
| **中途修改时间表** | 保存即生效。若把当前时段删掉/缩短到已过去，下一拍就判定"不生效"，拦截立即解除 |
| **中途修改番茄参数** | 立即生效，但锚点不变（仍是段起点），所以当前阶段的剩余时间会按新参数重算，可能突然变短 |
| **固化期间改设置** | 直接被拒绝：`自律固化中（21:30 结束），现在改不了设置`。只能等时段结束或用积分解锁 |
| **固化 + 时段结束** | 到点自动解除：拦截停、守护进程退出、任务管理器恢复可用、弹恭喜窗 |
| **全天生效的规则** | 因为"没有结束时间"，**不参与固化**（否则会永久锁死），只做普通拦截 |
| **目标程序以管理员运行** | 拦截失败，事件里写"权限不足，请以管理员身份运行"；本程序提权后即可 |
| **程序没运行** | 不拦截、不提醒；统计报告在下次启动时按日期补齐 |
| **系统时间被修改** | 以本地时间重新判定当前是否在段内，不做防篡改 |
| **多显示器 / 高 DPI** | 遮罩按每块屏的物理分辨率各自适配，混合缩放不错位 |
| **提醒阈值 > 阶段时长** | 不提醒（学习）/ 阶段一开始就提醒（休息） |

## 六、一句话总结

周时间表决定"什么时候进入自律"，番茄参数决定"自律与休息怎么切"，
提醒在两个阶段各自结束前按自定义分钟数各响一次（休息的可以单独关），
固化把这段时间锁死，积分是唯一的提前出口，结束时弹窗恭喜并结算积分。
