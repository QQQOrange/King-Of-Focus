## KOF-01（P0）全局 keydown 没有 Tab 分支

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 文件:行 | `ui/app.js:8223`（新增）；原问题在 `ui/app.js:10653` 的全局 keydown |
| 现象 | 弹窗打开后按 Tab，焦点顺着主界面的按钮一路跳；跳到弹窗外之后再按 Esc，反而把弹窗关了——用户描述为「焦点连续跳」「键盘乱跑」。根因：全局 keydown 只处理 Esc / Enter，没有 Tab 分支，也没 `preventDefault`，浏览器默认行为把焦点送出弹层。 |
| 修复要点 | ① 在 **capture 阶段**监听 Tab（子组件 `stopPropagation` 拦不住）；② 取栈顶层的可聚焦元素列表，手动算下一个（支持 Shift+Tab 反向、首尾环绕）；③ **无条件 `preventDefault()`**，把「焦点会不会跑出去」这件事从浏览器手里拿回来；④ 输入法组合中（`isComposing` / `keyCode 229`）不接管，交给输入法翻页选词；⑤ 层内没有可聚焦元素时给容器 `tabindex=-1` 并聚焦，保证 Tab 有落点。 |
| 验收标准 | ① 打开任意弹窗，Tab / Shift+Tab 只在弹窗内循环，最后一个元素后面回到第一个；② 焦点在弹窗内时按 Esc 能正常关闭；③ 连续按 Tab 10 次，`document.activeElement` 始终在 `.modal-mask` 内；④ 中文输入法组合中按 Tab 不改变焦点（交给输入法）。 |

## KOF-02（P0）没有「当前层」状态机

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 文件:行 | `ui/app.js:8048`（`const Layer`）；`#modalRoot` 的 15 处直写在 `ui/app.js:808/903/1752/…`（未改动） |
| 现象 | 即使拦住 Tab，也说不清「该在哪个范围里循环」：`#modalRoot` 一直是「谁想弹就 `innerHTML = …`」，没有栈、没有当前层概念。嵌套弹层（选择器叠在编辑器上、自查面板叠在任何地方）时无法判断谁是顶层，Esc 也不知道该关哪个。 |
| 修复要点 | 用 **MutationObserver 盯 `#modalRoot`** 维护层栈（`.modal-mask` 即一层）：新增入栈、消失出栈、自动记录打开前的焦点用于还原。刻意**不改那 15 处直写**——写法不变、行为统一，改动面最小。层名取自 `.modal-hd h3`，供提示与自查面板显示。 |
| 验收标准 | ① 打开弹窗后 `Layer.size() === 1`、层名等于标题；② 手动 append 第二个 `.modal-mask` 后 `size === 2`，栈顶是后加的那个；③ 关闭弹窗后栈归零；④ 关闭后焦点回到打开前的元素。 |

## KOF-03（P1）输入法组合中 Enter 提前提交 + 冒泡被吞

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 文件:行 | `ui/app.js:10669`（Esc 去重）、`ui/app.js:10674-10680`（IME / repeat 保护）；Esc 的 capture 版在 `ui/app.js:8243` |
| 现象 | ① 中文输入法拼到一半按 Enter（本意是选词），表单直接提交，存进去的是拼音；② 某些子组件 `stopPropagation()` 之后，Esc 到不了 `document`，弹窗关不掉，只能点 ×；③ 原 Esc 走冒泡，与新增的 capture 处理叠加时会「一次 Esc 关两层」。 |
| 修复要点 | ① Enter 分支前加 `if (e.isComposing || e.keyCode === 229) return;`；② 同时忽略 `e.repeat`（长按回车不再连建多条规则）；③ Esc 移到 **capture** 阶段统一处理，并给事件打 `__kofEscHandled` 标记，冒泡里的旧逻辑看到就跳过——既穿透 `stopPropagation`，又不会重复关层。 |
| 验收标准 | ① 组合中按 Enter：不提交（计数器不变）；② 组合结束后按 Enter：提交一次；③ 长按 Enter 只提交一次；④ 子组件 `stopPropagation` 时 Esc 仍能关掉当前层，且只关一层。 |

## KOF-04（P1）没有 keyup / 失焦兜底

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 文件:行 | `ui/app.js:8254`（keyup / window focus / visibilitychange 三处兜底）、`Layer.ensureInside` 在 `ui/app.js:8143` |
| 现象 | 焦点一旦跑到层外就再也回不来：切到别的窗口再切回来、点了一下主界面、Tab 被浏览器插件抢走——弹窗还开着，键盘却完全失效，只能鼠标点回去。 |
| 修复要点 | 三个时机调 `ensureInside()`：① `keyup`（Tab / Esc 抬起后；此时 `activeElement` 才是最终结果）；② `window` 的 `focus`（从别的窗口点回来）；③ `visibilitychange` 恢复可见。发现焦点不在栈顶层里就聚焦回层内第一个元素，并记一次「拽回次数」供自查面板显示。 |
| 验收标准 | ① 把焦点移到层外按钮后按一次 Tab 抬起，焦点回到层内；② 切出窗口再切回，焦点仍在层内；③ 自查面板的「拽回次数」随每次纠正 +1。 |

## KOF-05（P2）与 KE 没有事件通道

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 文件:行 | `ui/app.js:8263`（`SubLayerChanged` 派发在 `Layer.emit`，订阅示例在同处） |
| 现象 | 层变化对外完全不可见：键盘引擎 / 拖选 / 快捷键面板各自为战，没人知道「现在弹了几层、顶层是谁」。要做「弹层时暂停全局快捷键」这类联动只能靠轮询 DOM。 |
| 修复要点 | 层栈每次变化派发 `document.dispatchEvent(new CustomEvent('SubLayerChanged', { detail: { count, name, at, escapes } }))`；同时把同一份信息挂到 `S.uiLayer` 方便排查。首个消费者：时段页拖选在弹层出现时调用 `ccEdgeClear()` 收尾（避免拖到一半弹窗后留下悬停/手柄残留）。后续接键盘引擎只需 `addEventListener('SubLayerChanged', …)`，不用互相 import。 |
| 验收标准 | ① 打开弹窗后能在 `document` 上收到事件，`detail.count === 1`；② 关掉后收到 `count === 0`；③ 事件名字与字段稳定（`count / name / at / escapes`）；④ 订阅者不会因层变化报错（拖选页与其它页都试）。 |

## KOF-06（P2）提权不一致的 UIPI 隐患

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 文件:行 | `ui/app.js:3004`（快捷键卡片里的提示）；权限判定 `src-tauri/src/cmds.rs:35`（`is_admin`） |
| 现象 | 未提权时，强制退出用的低级键盘钩子收不到「以管理员身份运行」的窗口里的按键——这是 Windows 的 UIPI 隔离。以前界面上没有任何说明，用户会以为「快捷键没注册 / 程序坏了」。本次问题的成因不是它（两者都未提权），但属于同一类隐患。 |
| 修复要点 | 在「快捷键」卡片里按当前权限显示一段红字：说明 UIPI 限制、明确「这是系统限制不是没注册」、并指向已有的「以管理员身份重启」。不改变任何行为，只把不可见的限制写出来。 |
| 验收标准 | ① 普通权限下快捷键卡片出现 UIPI 说明，且带「以管理员身份重启」入口；② 管理员权限下该说明不显示；③ 文案不承诺「提权后一定能拦所有窗口」（有些反作弊窗口连提权也拦不住）。 |

## KOF-07（P3）没有键盘可发现性 / 自查入口

| 项 | 内容 |
|---|---|
| 优先级 | P3 |
| 文件:行 | `ui/app.js:3012`（设置页入口）、`ui/app.js:8277`（`renderKeyCheck`）、`ui/app.js:6612`（`Act.keyCheck`） |
| 现象 | Tab 逃逸、Esc 失效这类问题，用户只能描述成「焦点乱跳」，没有任何可观测值；开发复现也只能靠猜。 |
| 修复要点 | 设置 → 快捷键 加「键盘与焦点自查」按钮，弹出一个小面板，**它自己就是一个层**，实时（250ms）显示：当前层数 / 层名、可聚焦元素总数与焦点所在位置、焦点被拽回次数、当前权限。面板里放一个输入框和两个按钮，用户按 Tab 就能亲眼看到焦点是否只在面板内循环。 |
| 验收标准 | ① 点按钮打开面板，显示「1 · 键盘与焦点自查」「1 / 5」这类读数；② 按 Tab 时「焦点位置」跟着变，且始终 ≤ 总数；③ 焦点被外部抢走后数字回退且「拽回次数」+1；④ Esc 关闭面板，面板消失后不再刷新（无定时器泄漏）。 |

## 附：本次顺带修掉的两个隐藏缺陷

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 弹窗内部一刷新就关不掉 | 带实时读数的弹窗（进度、自查面板）按 Esc / 点 × 没反应，弹窗一直在 | `closeModal()` 的退场保护写的是「`#modalRoot` 有任何 childList 变化就放弃清理」，而内部 `textContent` 更新也会触发 childList | 只把「**新插入 `.modal-mask`**」算作新弹窗（`ui/app.js:8011`） |
| 嵌套弹层一关全关 | 两层叠着时按 Esc，两层一起消失 | `closeModal()` 取的是 `root.querySelector('.modal-mask')`（第一个 = 下层）并清空整个 `#modalRoot` | 多层时只摘栈顶元素（`Layer.closeTop`，`ui/app.js:8162`）；单层仍走原 `closeModal` 保留退场动画 |
