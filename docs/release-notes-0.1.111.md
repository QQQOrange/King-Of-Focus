# 0.1.111 — 修「遮罩下记一笔输入框被盖住」

## 现象

开遮罩时点 HUD 的「＋」记一笔，输入框被遮罩盖住：看不见、也点不到，
打出来的字直接落到遮罩上。而自律时段里「记一笔」是**唯一**能记录分心事件的入口。

## 原因

遮罩是置顶窗口，HUD 也是置顶。原来的逻辑是"只在检测到 HUD 被遮罩压住时才把它提上来"，
而那个检测有个前提：HUD 必须已经在置顶带里、并且紧邻遮罩。实际运行时，
用户点开输入框的那几百毫秒里，遮罩会重新把自己提到最前（换目标、重绘、摘顶扫描都会），
HUD 就被连同盖住；等下一轮检测时，它和遮罩之间还夹着别的置顶窗口，检测直接判"没被压住"，
于是**再也不提**。

## 修法

1. **遮罩每帧无条件把 HUD 钉在最前面**（只要 HUD 可见）。
   不再依赖"是否被压住"的推断——那是个概率判断，而这个入口不能有概率。
   代价只有每帧两次 `SetWindowPos`，遮罩本来就不是 60fps 重绘。
2. 新增 `hud_capture` 命令：HUD 打开输入框时立刻顶一次，不必等下一帧。
   关闭时不再需要恢复状态——遮罩本来就会继续把 HUD 顶住。

## 为什么不是"输入时临时关掉遮罩"

那会让"记一笔"变成短暂关闭自律的按钮——一个记录动作不该有这种副作用。
把 HUD 顶上去，遮罩仍然盖着其它一切，语义没变。

## 你需要验证的

1. 退出重开（0.1.111）。
2. 手动开遮罩（或进自律时段），点 HUD 左上角「＋」。
3. 输入框应该**在遮罩之上**，能正常输入；回车记下后输入框收起，HUD 仍在最上层。
