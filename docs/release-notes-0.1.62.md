# v0.1.62 · 权限与通知补齐：能申请、能降级、能说清

安卓 **0.3.9**。桌面端功能不变，只有版本号跟着走。

## 先修一个真漏洞：通知权限**从来没被申请过**

代码里只有 `checkSelfPermission`，没有任何一次 `requestPermissions`。
后果是 Android 13+ 上四类通知**一条都不会出现**，而且用户从没被问过——
他会以为「这软件就是不提醒」，而不是「我没授权」。

现在：第一次开启「自律总开关」时申请（此时才有内容可发），拒绝后写入
`notifAsked` / `notifBlocked`，界面按「还没开启 / 已拒绝 N 次 / 已被永久拒绝」
给三种不同的提示与动作。

## 权限清单：一处维护，三处一致

新增 `core/Permissions.kt` 作为**唯一数据源**（应用内清单、总览页、本文档读同一份）。
七项逐项回答：**用途 / 申请时机 / 申请方式 / 缺失影响 / 降级方案 / 重新授权**。

| 权限 | 申请方式 | 缺了会怎样 | 降级 |
|---|---|---|---|
| 应用列表 | 安装即得 | 选择器列表不全 | 按包名手动添加，规则照常生效 |
| 通知 | 运行时弹窗（13+） | 四类通知都不出现 | 应用内照常显示状态，统计/拦截不受影响 |
| 照片和视频 | **不申请** | 无 | 本应用没有相册场景，如实标「不需要」 |
| 悬浮窗 | 跳系统设置 | 锁机盖不住屏幕 | 拦截走「回桌面 + 通知」 |
| 使用情况访问 | 跳系统设置 | 统计完全停止 | 仅无障碍时仍能拦截，页面明说「统计已暂停」 |
| Shizuku | 第三方授权 | 拦不硬、不能强制结束 | 能力等级显示「增强」，功能全在 |
| 无障碍 | 跳系统设置 | 识别退化为 1 秒轮询 | 有使用情况访问时仍能拦，慢一拍 |

「照片和视频」是刻意**不申请**的：备份走 SAF、报表是文本、锁机背景是纯色，
没有任何读相册的场景。为了清单好看去要权限，既过不了审核也在骗用户。

## 通知：三类补齐，常驻加进度

| 通知 | 触发 | 样式 | 频率 |
|---|---|---|---|
| 常驻 | 自律或统计开启时 | 低优先级静默、不可划掉；`专注中 · 00:21 · 今日 0/60 分` + 进度条 + 副标题 | 正文每秒，进度 30 秒 |
| 阶段结束前 | 剩余时间到阈值 | 高优先级；`本轮专注还剩 5 分钟` | 每阶段一次 |
| **任务完成**（新） | 阶段切换那一刻 | `专注完成` / `休息结束` + `今日已自律 X/Y 分` | 每次切换 |
| **当日汇总**（新） | 每天到点（默认 22:00）且当天有记录 | `今日使用 3 小时 12 分` / `自律时段内 48 分（25%） · 用得最多：微信` | 每天一条 |

四类分属四个渠道，系统设置里可按渠道单独关；应用内也有独立开关与汇总时间可调。

三个刻意的取舍：

- **没数据不发，也不记账**：到点还没有记录就继续等——用户 22:30 才开始用手机，
  也还能收到当天汇总（否则「先记账再发」会让当天彻底收不到）。
- **完成只在阶段边界发**：手动关开关、切方案不算完成，否则是误报。
- **常驻进度只在有计划时显示**：`0/0 分` 比不显示更让人困惑。

顺带修了一个旧问题：**「休息结束前提醒」以前永远发不出来**——tick 在
`st.inBreak` 就 `return` 了，`maybeNotify` 根本没被调用。

## 总览页：今日自律总时长（分钟精度）

「今天」面板的时段色条下方新增一行，与色条同一份排班的两个视角：

```
今日自律总时长     共几段      最长一段
1 小时 30 分       2 段        1 小时
```

同时修正状态卡里的粗口径：以前是 `count { it.on }`（数整点），
`09:00–09:45` 会被算成 1 小时。现在两处共用 `Slots.dayMinutes`，
15 分钟刻度和「一小时多段」都算准。

## 验证（AVD 实测）

| 场景 | 结果 |
|---|---|
| 未授予通知权限 | 通知栏里**没有**本应用任何通知（复现了上面的漏洞） |
| 授予后 | 常驻：`King Of Focus · 自律中` / `专注中 · 00:21 · 今日 0/60 分` / 副标题 `今日自律 0/60 分` |
| 阶段切换 | 完成通知：`休息结束` / `开始下一轮专注，先做最重要的那件 · 今日已自律 0/60 分`（`channel=kof_done`） |
| 制造 30 秒使用数据 | 汇总：`今日使用 30 秒` / `自律时段内 10 秒（33%） · 用得最多：Settings`，`lastSummaryDay` 写回 |
| 总览页 | `今日自律 1 小时`；今天面板 `1 小时 / 1 段 / 1 小时` |
| 权限清单 | 7 项状态准确：应用列表「可见 242 个应用」、照片「不需要」、Shizuku/无障碍「去开启」 |
| 点开某一项 | 展开显示用途/时机/方式/缺失影响/降级/重新授权 |

测试：Android **178 条**全绿（新增 10 条：阶段切换判定、汇总四条件、跨天重置、
时间规范化、进度边界、清单完整性与申请历史累计）；桌面 Rust 252、UI 1032、i18n 658 全过。

## 一处 UI bug（顺手修）

权限清单的展开状态原本放在组件内部 `remember`，而这个页面**每秒重组一次**，
点了会立刻被重置回「全折叠」——表现为「点了没反应」。已把状态提到页面层。
