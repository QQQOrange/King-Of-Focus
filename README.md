# King of Focus

> 一个 Windows 上的专注 / 自律守护工具：按周计划拦住分心的软件和网页，用一个可调透明度的黑幕把屏幕盖上，并把你每天的时间花在哪记得清清楚楚。

- **版本**：0.0.1
- **开发者**：QQQOrange
- **项目地址**：<https://github.com/QQQOrange/King-Of-Focus>
- **本版本更新时间**：2026-10-26

## 一、它能干什么

| 模块 | 一句话说明 |
| --- | --- |
| 规则引擎 | 一条规则 = 一份名单（软件 / 网站分开维护）+ 一张周时间表。只在时间表里才生效。 |
| 黑名单 / 强制模式 | 黑名单：名单里的不许开；强制模式：只有名单里的能开，其他前台窗口一律关掉。 |
| 固化模式 | 生效期间不可退出、不可改设置，任务管理器一类的工具会被立刻关掉，杀了进程还会被拉起来。 |
| 番茄休息 | 专注 N 分钟 / 休息 M 分钟循环，休息期间黑名单放开，时间到自动锁回。 |
| 积分兑换 | 专注 1 分钟 1 分，积分可以用来强行解锁，单价随当天解锁次数递增。 |
| 专注遮罩 | 选一个窗口留下，其余区域被圆角遮罩盖住，从窗口边缘向外扩散，透明度/圆角/时长可调。 |
| 桌面 HUD | 屏幕右上角常驻小窗：专注时长、剩余时间、定时换新的励志短语，跟随主题。 |
| 时长统计 | 每秒采样前台窗口，按「自律模式开启 / 未开启」两套数据独立记录。 |
| 统计报告 | 日 / 周 / 月 / 年 + 自定义 N 天，自动生成饼图报告，可随时回看。 |
| 云同步 | 走你自己的 WebDAV（坚果云 / Nextcloud / 群晖），手动或定时同步规则。 |
| 自动更新 | 启动检查 GitHub Releases，弹窗提示 → 下载 → 退出 → 静默安装 → 重新启动。 |
| 外观 | 深色 / 浅色 / 跟随系统，实时切换，HUD 同步。 |

## 二、核心概念

### 1. 规则的生效逻辑

```
当前时间  ∈  某条已启用规则的时间表  →  这条规则「生效」
至少一条规则生效                        →  自律模式 = 已开启
```

- 时间表按 **周一 ~ 周日** 划分，每天可以有多段（例如 08:00-11:30、14:00-17:00），支持跨夜。
- **时间表全空 = 7×24 小时生效**，适合"永久封禁"的规则。
- 下周自动循环，不需要重复配置。

### 2. 软件与网站是分开的

| | 软件 | 网站 |
| --- | --- | --- |
| 名单存在哪 | 规则的「软件」页 | 规则的「网站」页 |
| 谁来执行 | Rust 主程序（枚举前台窗口 → 关闭进程） | 浏览器插件（`declarativeNetRequest` 重定向到拦截页） |
| 匹配方式 | exe 完整路径 / 文件夹 / 进程名通配 / 窗口标题 | 域名 / 路径前缀 / `*` 通配 |
| 例外 | — | 「网站例外」页，优先级高于黑名单 |

### 3. 强制模式（白名单）

开启后，生效时段内**只有名单里的软件能被前台显示**，其他有可见窗口的程序会被关闭。

保护机制（这些永远不会被拦）：

- 本程序自身、`explorer.exe`（桌面/任务栏）
- 路径位于 `C:\Windows\` 下的所有系统进程
- 「设置 → 全局保护名单」里的进程名（默认已内置几十个系统组件）

### 4. 专注遮罩

选一个窗口作为"允许留下的画面"，屏幕其余部分被遮罩覆盖：

- **任务栏永远不遮**：区域挖洞和逐像素两种模式都会把任务栏（主屏 + 副屏）从遮罩里扣掉，
  开始菜单、托盘浮出层照常被压暗
- **跟随自律模式**：打开后自律一开始就自动开遮罩、自律一结束自动关；此时主开关显示为"由自律驱动"、不可手动切换
- **预览不等于开启**：「预览效果」只持续 5 秒并自动收起，不会把主开关改成"已开启"，状态栏会明确显示"预览中"
- **跟随当前窗口**（可选）：不用选目标，遮罩自动盯住**当前最上层窗口**，只留它可见；
  切换窗口时洞口平滑移过去（时长＝下面的动画速度），拖动窗口时 1:1 实时跟随
- **扩散动画**：开启动画时，遮罩从目标窗口的边缘向外铺满它所在的显示器，关闭时反向收回
- **不透明度** 20% ~ 100%，滑块拖动即时生效（遮罩开着时能直接在屏幕上看到效果）
- **边缘留白** 0 ~ 60 px
- **圆角半径** 0 ~ 80 px，扩散过程中圆角保持一致
- **动画速度** 0 ~ 3000 ms（0 = 瞬间），缓动曲线 easeOutCubic；数值越大越慢
- **两种渲染方式**：默认「区域挖洞」（整窗半透明黑 + `SetWindowRgn` 挖掉目标窗口，兼容性最好，
  但圆角是 1px 硬台阶）；可切「高清圆角」用逐像素 alpha，**边界像素按洞覆盖率做亚像素混合**，
  圆角在任何半径下都是平滑的。个别显卡/远程桌面不支持逐像素时会自动降级回区域画法并在界面上标注，
  把开关关掉再打开即可重试。切换后自动记住，不用点保存
- **屏蔽鼠标操作**（可选）：开了就吃掉所有点击；关掉则纯视觉，鼠标可穿透
- 目标窗口**关闭 / 最小化时遮罩自动退出**，不会把你困在黑屏里（有 1.5 秒宽限，切窗口抖动不会误退）
- 全局热键 **Ctrl + Alt + K** 随时开关
- **「自查」按钮**：直接读遮罩线程最后一帧的真实状态（`on / painted / alpha / 洞口 / 每个覆盖层是否可见`），
  遮罩万一没出现，点它就能看出卡在哪一步，不用猜
- 运行期每 500ms 把遮罩重新压到最上层：后打开的全屏视频、游戏启动器这类置顶窗口抢不走它

### 4.1 浏览器插件巡检（自律时段的最后一道锁）

浏览器里的网页拦截靠插件完成，所以"插件没装/没开"必须能被发现并处理：

- **启动时自动识别**已安装的浏览器，并逐个判定插件处于三种状态之一：
  - `未安装`：所有配置档里都找不到本插件
  - `已启用`：至少一个配置档里 `state=1` 且没有 `disable_reasons`
  - `已停用`：找到了，但在扩展管理页里被关掉
  - （Firefox 只识别、标记为"不支持本插件"，不参与拦截）
- **安装引导**：任一浏览器"未安装/已停用"时弹一次提示，写明缺少插件会导致
  ① 网页黑名单失效 ② 自律时段打开该浏览器会被自动关闭；按钮为「去安装」/「稍后再说」。
  点「去安装」会打开该浏览器的扩展管理页，并给 **10 分钟保护期**（这期间不会关浏览器）。
  页面里常驻一块"扩展文件夹"面板：完整路径 + **一键复制** + 打开文件夹，复制/打开都有成功与失败反馈，
  路径缺失时给出替代方案（打开程序目录拖 CRX / 重新解压完整包）。
- **自律时段监控**：任意规则处于生效状态时，每轮轮询（默认 0.8~1 秒）检查一次；
  发现浏览器正在运行而插件未就绪 → 先弹提示卡，宽限 `graceMs`（默认 1200ms，上限 3500ms）后关闭，
  **整体不超过 5 秒**；先温和关闭、0.4 秒不退再强制结束。
- **检测频率**：启动全量扫一次；后台每 20 秒刷新缓存；自律时段每轮用缓存判定。
- **失败处理**：关不掉时（多为浏览器以管理员运行而本程序不是）记一条"关闭失败"，
  每 60 秒重试一次，并提示以管理员身份运行。
- **记录**：写入拦截记录（`kind=browser`），含时间、浏览器名+窗口标题、原因（插件未安装/被停用），
  在「总览」事件列表里以蓝色"浏览器"标签展示。

### 5. 固化模式（硬核锁定）

在规则编辑器的「固化」标签里打开 `硬核锁定` 后，该规则的生效时段会变成"不可破解"状态：

| 维度 | 行为 |
| --- | --- |
| 退出程序 | 托盘退出、`quit_app` 命令都会被拒绝，窗口只能收进托盘 |
| 修改设置 | `save_config` 直接返回错误，规则开关、名单、时间表、外观全部置灰 |
| 任务管理器 | `taskmgr / procexp / ProcessHacker / SystemInformer / msconfig / regedit / autoruns` 一出现就被关闭 |
| 杀进程 | 主进程被杀后，`--guard` 守护进程会在 2 秒内把它拉起来（最多连拉 40 次） |
| 解除 | 时段自然结束 / 用积分解锁 |

**边界情况**：

- 守护进程只在锁定时存在，解锁后自己退出，不会常驻占资源
- 心跳文件写在数据目录，超过 8 秒没更新就判定"主进程已死"
- 守护进程自身被反复杀死时，40 次后会放弃，避免变成 fork 炸弹
- 拦截"任务管理器"时只匹配有可见窗口的进程
- 以管理员运行的目标程序需要本程序也提权才能关掉，失败会在事件里写明"权限不足"

### 5.1 自律时段内的守卫范围

「自律时段」进行中（`clockInWindow`，**专注段与休息段都算**）时，下面这些操作会被后端直接拒绝——
界面先置灰一道，但真正把关的是命令层，直接调命令也绕不过去：

| 操作 | 为什么拦 |
| --- | --- |
| 「自律时段」总开关（开、关都不行） | 换一个状态就等于当场取消/重置自律 |
| 「规则」页里任何一条规则的启用开关（开、关都不行） | 关掉是放行；时段内让开关整体不可动，避免"开着开着偷偷改了" |
| 切换 / 删除正在生效的那套「星期时段」方案 | 切到更松的一套 = 一键绕过 |
| 关「时段内让规则立即生效」 | 等于当场取消自律 |
| 取消已选时段 / 改正在生效这一小时的专注与休息时长 | 换一种方式提前结束 |
| 删除规则、从已启用规则里删软件 / 删网站 / 加"网站例外" | 同样是放行，只是绕了远路 |
| **进入测试模式** | 测试模式换一份配置，且会关掉所有纪律校验 |
| **恢复备份 / 云端同步下载** | 整份配置覆盖，可把"规则已关闭"的旧配置搬回来 |
| **自动更新 / 切换管理员模式** | 两者都要真的退出进程再起来 |

守卫的门槛是"在不在选中的小时里"，不是"是不是专注段"：一个 50/10 的时段里，
只在专注段锁定等于每小时送你 10 分钟随便改，所以休息段同样锁死。
只拦"会让这段自律失效"的改动；改外观、改统计、改提醒、往规则里**加**条目都不受影响。
测试模式下不拦（测试模式的意义就是随时开关）。

### 5.2 「星期时段」：多套方案

「自律时段」页里排的是**一张周表**：7 列（周一到周日）× 24 行（0–23 点），粒度 1 小时。

- **多套方案**：可以并存多套周表（工作日强化 / 周末轻松 / 假期……，上限 12 套），
  顶部「星期时段」那排按钮就是方案切换器。同一时刻只有**一套**在生效，
  `focusClock.active` 指向它；切过去立刻按新方案判定，原来那套原样留着。
- **方案自带通用时长**：「通用时长」跟着方案走，新框选的小时沿用当前方案的那套专注 / 休息。
- **连续时段自动合并**：同一列里连续的小时画成**一整块**（跨多天同一时段的还会横向连成一条），
  中间没有接缝；块内的浅色横条是各小时的休息段。
- **方案操作**：新建（空表）/ 重命名 / 复制这套 / 删除这套（至少保留一套）。
- **数据结构**：`settings.focusClock.profiles[]` + `active`。
  老配置里的单套 `days`（以及更旧的 `hours`）在加载时自动迁成第一套方案，
  `sanitize` 后旧字段清空，不会出现"两份真相"。

### 6. 番茄休息

规则的「休息」标签页里可以设成番茄：`专注 N 分钟 → 休息 M 分钟` 循环，从时段起点开始算。

- 休息段内这条规则**不拦截**，黑名单里的软件和网页都能用
- 休息不算自律时间（不加积分），休息期间也可以退出程序
- 时间一到自动锁回，HUD 上的圆点会变绿并显示"休息中"
- 时段建议留够整轮，例如 19:00-21:30 配 50/10

### 7. 积分与强行解锁

| 规则 | 数值 |
| --- | --- |
| 获得 | 处于工作段时每分钟 +1 分 |
| 解锁单价 | 15 分 / 分钟 × 1.4^(今天已解锁次数)，第 1 次 15、第 2 次 21、第 3 次 29…… |
| 可选时长 | 5 / 10 / 15 分钟 |
| 解锁后 | 所有拦截暂停、可以退出程序、守护进程退出，倒计时结束自动恢复固化 |
| 退还 | 提前结束不退分；积分本身不清零，解锁次数每天重置 |

换算下来：专注 75 分钟能换第一次 5 分钟自由，第二次就要 105 分钟。次数递增是为了让"解锁"始终是件肉疼的事。

### 8. 桌面 HUD

自律期间在屏幕右上角浮一个 272×122 的小窗：

- 置顶、不进任务栏、无边框、圆角、半透明毛玻璃
- 显示：状态（专注中 / 休息中 / 固化专注中）、已专注时长、距结束时间、一句励志短语
- 短语来自 [一言](https://hitokoto.cn) 接口，按设置间隔（默认 60 分钟）自动换新；断网时用内置的 14 句轮换
- 跟着主题走，浅色模式下自动切成白底
- 可以按住拖动到别的位置

### 9. 拦截后的行为

黑名单命中时的统一动作链：

**① 弹通知 → ② 温柔关闭 → ③ 0.7 秒不退则强杀 → ④ 把主程序窗口拉到前台并跳到首页**

- 通知：屏幕右上角弹一张圆角卡片，写明「哪个应用 / 哪个网址 + 命中的规则」，停留 4 秒自动收起；
  它压在专注遮罩之上，所以开着遮罩也看得见。同一目标 1.5 秒内只弹一张，不会刷屏
- 通知到关闭之间隔一次轮询（默认 800ms），所以你一定能先看到提示、再看到它被关掉
- 触发条件：目标进程有可见窗口（拿不到路径的一律放过，避免误杀）
- 多次触发：同一次拦截只记录一条事件；主窗口聚焦做了 1.5 秒防抖，避免反复抢焦点
- 跳转失败：窗口被最小化/隐藏时先 `unminimize + show + set_focus`，任何一步失败都只是静默跳过，不影响拦截本身
- 网页拦截：插件先回调 `/api/report`（→ 弹通知），等 900ms 再动手关。关什么由设置里的
  「网页被拦时关闭整个浏览器」决定：开 = 关掉整个浏览器窗口，关 = 只关那一个标签页

## 三、技术方案

### 为什么是 Tauri 2 + Rust 原生 Win32

这个工具的核心是"每秒看一眼前台窗口，该关的立刻关掉"，性能与权限是硬指标：

| 方案 | 问题 |
| --- | --- |
| Electron + tasklist 轮询 | 每秒拉起子进程，CPU 抖动明显；杀进程还要走 `taskkill`，延迟 100ms+ |
| 内核驱动（Cold Turkey 的做法） | 拦得最彻底，但要签驱动、蓝屏风险、维护成本极高 |
| **Tauri 2 + 原生 Win32 FFI** | 单次枚举 ~1ms，常驻内存 40MB 左右，无运行时依赖，一个 exe 走天下 |

所以后端是 **纯 Rust**，直接 FFI 调用 `user32` / `kernel32`，没有引入任何 Windows 封装 crate：

```rust
EnumWindows → IsWindowVisible → GetWindowTextW        // 枚举有可见窗口的应用
GetWindowThreadProcessId → OpenProcess → QueryFullProcessImageNameW  // 拿到 exe 路径
PostMessageW(WM_CLOSE) → TerminateProcess             // 两段式关闭
```

### 专注遮罩：逐像素 alpha 的圆角扩散动画

**没有**用矩形拼条拼遮罩（拼条做不出圆角，也做不出连续形变），而是：

```
每台显示器 = 1 个 WS_EX_LAYERED 窗口 + 1 张 32bpp 预乘 ARGB 位图
        └─ UpdateLayeredWindow 提交给 DWM 合成
位图内容 = 整块遮罩色 + 中间抠一个圆角矩形"洞"
动画     = 洞从「整块显示器」插值收缩到「目标窗口 + 边距」
```

关键点：

- **零缩放变形**：位图尺寸 = 该显示器的物理像素尺寸，不做任何拉伸；窗口本身也不缩放，
  所以任何分辨率 / 宽高比下 1 px 就是 1 px，不会模糊或裁切
- **圆角是画出来的**：第 `y` 行的洞水平区间按圆角公式 `inset = r - sqrt(r² - (r-dy)²)` 计算，
  半径在整段动画里保持不变
- **抗锯齿靠亚像素混合，不是靠公式本身**：区间保留浮点（`span_f`），边界像素按"被洞吃掉的
  比例"算 alpha（`paint_row` / `shade`）。这一条是「高清圆角」和「区域挖洞」唯一实质区别——
  一旦把边界 `round()` 成整像素，两套画法在视觉上就完全一样了
- **降级与重试**：ULW 失败时该覆盖层永久改用区域画法（`use_region`），且**不参与画法切换判断**，
  否则会出现"失败→判成需要切换→重建→再失败"的每帧重建死循环；用户把开关关掉再打开时清掉降级结论，给一次重试
- **缓动**：`easeOutCubic`，前 35% 时长透明度同步淡入，出场反向并加快 1.6 倍
- **静止不重绘**：只有「洞 + 透明度 + 半径 + 进度」这个 key 变化时才重画；
  每帧一次整屏填充 + 洞内清零，边界只多算 2 个像素，抗锯齿几乎不增加成本
- **多显示器**：`EnumDisplayMonitors` 枚举，每块屏独立位图独立窗口；显示器增删会自动重建
- **高 DPI**：遮罩线程内 `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，
  全程用物理像素，混合缩放比例下洞口和窗口严丝合缝

### 进程拦截：两段式关闭

1. 先 `PostMessage(WM_CLOSE)` —— 让程序自己退，能保住现场
2. 700ms 后仍在运行 → `TerminateProcess` 强制结束

可以在设置里关掉"先温和关闭"。**拦截失败最常见的原因是权限不足**：目标程序以管理员运行而本程序不是，界面上会明确提示并给"以管理员身份重启"按钮。

### 时长统计：1 秒采样 + 小时桶

```
每秒一次：
  前台窗口 pid → exe 路径
  若前台是浏览器 且 插件 5 分钟内上报过标签页 → 记到「域名」上
  否则                                        → 记到「exe」上
  无操作 ≥ 60 秒                              → 不计时（可关）

落到 stats/days/YYYY-MM-DD.json：
  { "on":  { "app|c:\\…\\chrome.exe": {label, category, secs, hours[24]} },
    "off": { "site|youtube.com":       {…} } }
```

- 内存里累加，**每 15 秒落盘一次**，退出时再 flush 一次
- 日文件按小时分桶（0-23），所以能回溯到"某天某小时"
- 双轨数据在同一个文件里但是两个独立 map，**永不混合**

### 浏览器插件：DNR 拦新导航 + JS 关已开的页

插件的目标很明确：**黑名单网页不该出现在屏幕上**。做到这点需要两道防线，缺一不可：

| 防线 | 覆盖场景 | 手段 |
| --- | --- | --- |
| ① 请求层 | 你**新打开**一个黑名单网址，请求还没发出去 | `declarativeNetRequest` 改写成 `blocked.html` |
| ② 页面层 | 规则生效时**已经开着**的标签页 | JS 扫描全部标签 → 通知 → 关标签/浏览器 |

第 ② 条是 DNR 做不到的：DNR 只作用于"新发起的请求"，页面已经渲染完它就不管了。
所以插件里有一份独立的 URL 匹配器（`matcher.js`，和服务端语义一致、可脱离浏览器单测），
并且：

- 规则一刷新就立刻扫一遍全部标签页（不用等你切过去）
- 切标签 / 新开标签 / 地址变化时**单页即时判定**，比定时器更快
- 关之前先 `POST /api/report` 让主程序弹通知，等 900ms 再关 —— 你会先看到提示再看到页面消失
- 窗口里只剩一个标签时不硬关（否则浏览器窗口直接没了），就地换成拦截页
- 主程序连不上 → 立刻清空规则并停止清理，避免主程序退出后浏览器被永久锁死

- `chrome.alarms`（最小 30 秒）拉取 `http://127.0.0.1:27315/api/state`
- 把规则翻译成 `declarativeNetRequest` 动态规则：
  - 黑名单网站 → `priority: 2` 重定向到 `blocked.html`
  - 网站例外 → `priority: 3` `allow`
  - 强制模式 → `priority: 1` 全拦 `*` + `priority: 4` 放行白名单
- 域名用 `requestDomains`（含子域），路径/通配用 `regexFilter`
- 切标签 / 页面加载完成立刻 POST `/api/heartbeat`，把 URL 报给主程序（统计用）
- 主程序侧有「浏览器守护」：要拦网页时插件失联超过 90 秒就关掉浏览器

### 云同步：WebDAV + last-write-wins

```
PUT  {dav 目录}/king-of-focus.json    上传（Basic Auth）
GET  {dav 目录}/king-of-focus.json    下载
```

- 载荷带 `updatedAt` 时间戳：云端更新就拉、本机更新就推、一样就跳过
- 账号密码只留本机，不随配置上传
- 404 视为"云端还没有文件"，自动转为首次上传
- 401/403/409/507 等状态码都翻译成中文提示

### 自动更新：Release → 标签 → 源码版本，三层兜底

```
GET api.github.com/repos/QQQOrange/King-Of-Focus/releases/latest
  → 比较 tag_name 与本机版本（语义化比较）
  → 优先选 *_Setup*.exe 资产
  → 下载到 %TEMP%\KingOfFocus\updates\（校验 MZ 头，防下到错误页）
  → 写一个 apply-update.cmd
  → app.exit(0)
```

`apply-update.cmd` 干这四件事：**等进程退出 → 删掉旧安装包 → `/S` 静默安装新包 → 启动新版本**，最后删掉自己和安装包。

GitHub 未登录的 API 额度是 60 次/小时，登录后 5000 次/小时。「关于」页可以填个人访问令牌提升额度，输入框是掩码，旁边 `?` 直接打开官方创建教程，并实时显示 `剩余 / 总额度`。

### 运行时数据位置（便携模式）

**所有数据都在软件目录下的 `king of focus data` 文件夹里**，跟着 exe 走，拷走整个文件夹就能迁移/备份：

| 内容 | 路径 |
| --- | --- |
| 配置（规则、设置、令牌） | `king of focus data\config.json` |
| 每日统计原始数据 | `king of focus data\stats\days\YYYY-MM-DD.json` |
| 统计报告 | `king of focus data\stats\reports\{period}_{start}_{end}.json` |
| 报告生成记录 | `king of focus data\stats\sched.json` |

## 五、时长统计与报告的完整口径

### 采集

| 项目 | 说明 |
| --- | --- |
| 采样频率 | 1 秒 |
| 归属对象 | 当前**前台窗口**（不是所有运行中的程序） |
| 软件字段 | `label`（进程名）、`category="app"`、`secs`、`hours[24]` |
| 网页字段 | `label`（域名）、`category="site"`、`secs`、`hours[24]` |
| 计入条件 | 有键鼠操作；或开启了"计入无操作时间" |
| 排除 | 拿不到 exe 路径的进程 |

> 浏览器当前打开的网址由插件上报（切换标签、页面加载完成时立即上报）。所以**网页时长依赖插件**；没装插件时，浏览器的时间会记到 `chrome.exe` / `msedge.exe` 上。

### 两种状态

| 状态 | 判定 | 存储 |
| --- | --- | --- |
| 自律模式**已开启** | 规则生效中 / 自律时段专注段 / 固化锁定中，任一成立 | 日文件里的 `on` |
| 自律模式**未开启** | 以上都不成立（含番茄休息段） | 日文件里的 `off` |

判定口径与拦截引擎、HUD、界面徽标完全一致：**界面说"自律中"，统计就一定记在 `on`**。
两者采集方式完全相同，但落在**两个独立的 map**，互不混合。

### 报告生成时机

| 周期 | 覆盖范围 | 生成时间 |
| --- | --- | --- |
| 日报 | 前一天 | 每天 00:00 |
| 周报 | 上周一 ~ 上周日 | 每周一 00:00 |
| 月报 | 上一个自然月 | 每月 1 日 00:00 |
| 年报 | 上一个自然年 | 每年 1 月 1 日 |
| 自定义 | 上一个完整 N 天 | 每个第 N 天的 00:00 |

- 判定循环每 30 秒跑一次，用 `sched.json` 记住"已经生成到哪一期"，所以**程序没开着也不会漏，下次启动自动补齐**
- 同一期只会生成一次，可在「统计报告」页手动重新生成
- 报告可以随时点开回看（含两份独立饼图 + 一份汇总饼图），也可单独删除

### 汇总口径

「两种状态汇总」这张饼图 = 把 `on` 和 `off` 两个数据集里**同一个应用 / 同一个域名**的秒数**直接相加**，不做任何加权、不做时间轴对齐。

扇区含义：该项在所选时间段内占全部前台时长的比例。

## 七、已知限制

- **只在 Windows 上工作**：大量 Win32 调用，没有跨平台打算。
- **不是内核级拦截**：和驱动级方案（Cold Turkey）比，理论上可以用"另一个管理员程序抢先"这类方式绕过。对自律场景够用，对"防别人破解"不够。
- **强制模式偏激进**：只关闭"有可见窗口"的进程，所以后台服务不受影响；但仍建议先开「演练模式」跑一天，确认名单没写错。
- **统计依赖前台窗口**：同一屏并排看两个窗口时，只有当前选中的那个计时。
- **令牌与密码是明文存在配置文件里**：只在本机，界面掩码显示。后续可以接 Windows DPAPI 加密。
- **云同步只同步规则与设置**：原始统计（几十 MB）不上传，避免把小网盘塞满。
- **便携存储**：数据放在 exe 同级目录，所以别把 exe 单独拷走（配置不会跟着走）。想迁移就整个文件夹一起搬。
- **更新需要 Release 里带 `*Setup*.exe` 资产**：没有安装包时弹窗会提示"该版本还没有上传安装包"。
- **测试模式是明确的"后门"，只是被上了锁**：自律时段**开始前**就进测试模式，之后到点的自律时段不会生效
  （测试模式的意义就是随时开关）。所以入口在自律时段内是禁用的；要真正靠它自律，别在时段开始前待在里面。
- **"以管理员模式启动"每次都要过一次 UAC**：这是 Windows 的规则，程序无法记住授权。
  拒绝 UAC 后 120 秒内不会再弹，本次以普通权限继续运行（设置里会显示"当前是普通权限"）。
- **本机 HTTP 服务没有鉴权**：只监听 `127.0.0.1`，但任何本机程序（含浏览器网页）都能读 `/api/state`。
  只影响"规则内容"这类非敏感信息，不含令牌与密码。

## 八、发版流程

1. 改 `src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 的版本号
2. 改 `src-tauri/src/version.rs` 里的 `BUILD_DATE`（关于页显示"本版本更新时间"）
3. `cargo build --release`，打包 NSIS 安装包
4. 在 GitHub 建一个 tag（如 `v0.0.2`），上传 `KingOfFocus-Setup-0.0.2.exe`
5. 老版本启动时会自动检测到并提示更新
